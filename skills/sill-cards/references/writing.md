# 书写规范

助手自己写的标题、卡面摘要和正文，语气和措辞由助手决定；结构和必写内容按各类型的模板（见[类型索引](types.md)），并守住两条：不超字数，格式用对。每张卡都写 `summary`。

导入外部原文是例外：`body` 写完整原文，不缩写、不摘要、不只取开头，规则见[导入细节](import.md#正文完整与清理)。用户另有要求（例如「只存摘要」）时按用户要求，并在正文开头注明不是全文。

## 字数上限

| 字段 | 上限 |
| --- | --- |
| `title` | 1–1000 字 |
| `summary` | 10000 字 |
| `body` | 500000 字 |
| `state.note` | 4000 字 |
| `tags` | 100 项，每项 100 字 |
| 整个请求 | 512 KiB UTF-8 字节，含参数与 JSON 编码 |

其他字段的上限见[字段字典](fields.md)。超限会被拒绝；正文太长时可拆成几张卡，见[传输规则](transport.md#日期单位与大小)。

供参考：手机卡面的标题最多显示 2 行，摘要显示 2–4 行，超出部分以「…」截断；桌面不截断，详情页显示全文。

## 格式

- `title`、`summary`：纯文本，不写 Markdown，不换行。
- `body`：一个 CommonMark Markdown 字符串，段落之间空一行，不传数组。标题、列表、引用、代码块、表格等按内容自由使用；文章详情会根据 `##` 小标题生成目录。不要把整个正文包进代码块。
- 正文图片保留 Markdown 语法和原文位置，仅加载无内嵌凭据的 HTTPS 地址；HTML 按纯文本显示，链接只支持 http、https、mailto。
- 可勾选的任务、会议、附件、章节、转录、PR 状态和关联卡片要写进对应的结构字段，正文里的 Markdown 复选框或链接列表不会变成这些结构。
- 详情页不显示卡面摘要。
- 阅读时长由客户端按正文计算，不需要写。
