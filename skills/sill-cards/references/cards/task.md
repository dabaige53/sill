# task：待办

一件要做、能拆成几步勾选的事。只是到点提醒一下用 [reminder](reminder.md)。

示例是合成资料，只展示 `sill_createContent` 参数里外层的 `body` 对象，不能当作用户资料保存。通用要求见[类型索引](../types.md)，字段格式见[字段字典](../fields.md)。

## 显示

卡面：来源行（完成数）→ 标题 → 清单前三项（未完成在前）。详情：到期、项目等信息行 → 完整清单 → 正文。

## 填写清单

| 字段 | 要求 | 怎么写 |
| --- | --- | --- |
| `title` | 必填 | 动词开头，说清要完成的结果 |
| `summary` | 必写 | 为什么要做、做到什么程度算完 |
| `tasks` | 必填 | 1–100 项，一项一个可执行动作；`id` 用稳定的短英文 |
| `due` | 有就写 | 截止时刻，13 位 Unix 毫秒；来源里有截止时间必须写 |
| `project` | 有就写 | 所属项目 |
| `url` | 有就写 | 议题或任务原地址 |
| `body` | 建议 | 完成条件、背景、注意事项 |
| `sources` | 必写 | `github`、`linear` 或用户口述 `capture` |

## 写法

已完成的子任务写个人状态 `state.taskDone`，不写在任务项上。正文里的 Markdown 复选框不能勾选，不要用。

正文结构：

```markdown
## 完成条件

做到什么算完。

## 背景

为什么要做。
```

步骤写进 `tasks`，正文只写条件和背景。

## 示例

```json
{
  "type": "task",
  "title": "准备周五产品评审",
  "summary": "周五 14:00 评审前，把范围和验收条件整理成可以直接讨论的材料。",
  "tasks": [
    {
      "id": "scope",
      "text": "整理本轮需求范围"
    },
    {
      "id": "acceptance",
      "text": "为每项验收条件写一个实际例子"
    },
    {
      "id": "demo",
      "text": "录一段 3 分钟的流程演示"
    },
    {
      "id": "send",
      "text": "周四 18:00 前把材料发给参会人"
    }
  ],
  "due": 1793872800000,
  "project": {
    "name": "产品评审"
  },
  "body": "## 完成条件\n\n参会人会前能看完材料，评审时只讨论未确认的问题。\n\n## 背景\n\n上次评审因为验收条件理解不一致，多开了一次会。",
  "state": {
    "taskDone": [
      "scope"
    ]
  },
  "sources": [
    {
      "name": "用户安排",
      "kind": "capture"
    }
  ]
}
```

## 写入前自检

- 每个子任务都是一个能直接动手的动作
- 截止时间写进 `due`，是 13 位毫秒
- 子任务 `id` 不重复
