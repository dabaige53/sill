# suggestion：建议

助手提出的一个具体下一步，附上理由和依据卡片。

示例是合成资料，只展示 `sill_createContent` 参数里外层的 `body` 对象，不能当作用户资料保存。通用要求见[类型索引](../types.md)，字段格式见[字段字典](../fields.md)。

## 显示

卡面：来源行 → 标题 → 摘要 → 最多两张引用卡。详情：正文和全部引用卡。

## 填写清单

| 字段 | 要求 | 怎么写 |
| --- | --- | --- |
| `title` | 必填 | 建议本身，动词开头 |
| `summary` | 必写 | 为什么现在做，一句话 |
| `body` | 必填 | 建议、理由、适用条件 |
| `related` | 有就写 | 作为依据的 Sill 卡片 ID |
| `sources` | 必写 | `agent` |

## 写法

一张卡只提一个建议；没有依据的猜测不写成建议。

正文结构：

```markdown
## 建议

具体做什么。

## 理由

依据和数据。

## 适用条件

什么情况下不适用。
```

## 示例

```json
{
  "type": "suggestion",
  "title": "评审前为每项验收条件补一个例子",
  "summary": "上次评审有两项条件理解不一致，补上例子能少开一次会。",
  "body": "## 建议\n\n在评审材料里，每项验收条件下面加一个真实操作的例子。\n\n## 理由\n\n上次评审记录里，「导出完整」和「提醒准时」两项各有两种理解，最后加开了一次会。\n\n## 适用条件\n\n条件已经很具体、没有歧义时可以跳过。",
  "sources": [
    {
      "name": "助手整理",
      "kind": "agent"
    }
  ]
}
```

## 写入前自检

- 只提一个建议
- 理由能在已有卡片或资料里找到
