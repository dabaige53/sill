# event：日程

有开始和结束时间的安排：会议、约见、行程、课程。

示例是合成资料，只展示 `sill_createContent` 参数里外层的 `body` 对象，不能当作用户资料保存。通用要求见[类型索引](../types.md)，字段格式见[字段字典](../fields.md)。

## 显示

卡面：日期行（相对时间）→ 时间段 → 标题 → 地点或会议 → 参会人；会议开始前 10 分钟出现「加入」。详情：日期、时间段、标题、会议与地点、参会人，正文作为议程。

## 填写清单

| 字段 | 要求 | 怎么写 |
| --- | --- | --- |
| `title` | 必填 | 会议或安排的名称 |
| `summary` | 必写 | 这次要决定或完成什么 |
| `start`、`end` | 必填 | 13 位 Unix 毫秒，按用户时区换算，`end` 晚于 `start`；全天事件写当天 00:00 到次日 00:00 |
| `location` | 有就写 | 地点 |
| `meeting` | 有就写 | 线上会议名称、链接、会议码；不写密码 |
| `people` | 有就写 | 参会人，只写来源里有的 |
| `body` | 建议 | 议程、要准备的东西 |
| `sources` | 必写 | 日历导入写 `calendar` |

## 写法

时间先写成带时区的 ISO 时间再换算毫秒，例如 `2026-11-03T14:00:00+08:00` → `1793685600000`；写入后换算回来核对。

正文结构：

```markdown
## 议程

1. 议题

## 会前准备

- 要看的材料
```

## 示例

```json
{
  "type": "event",
  "title": "产品评审",
  "summary": "确认本轮范围和验收条件，会后定下开发排期。",
  "start": 1793685600000,
  "end": 1793689200000,
  "location": "3 楼会议室 A",
  "people": [
    "林青",
    "吴同",
    "陈默"
  ],
  "meeting": {
    "name": "线上会议",
    "url": "https://example.com/meeting/review",
    "code": "482 913 557"
  },
  "body": "## 议程\n\n1. 演示当前流程（10 分钟）\n2. 逐项确认验收条件（30 分钟）\n3. 定排期（20 分钟）\n\n## 会前准备\n\n- 阅读评审材料",
  "sources": [
    {
      "name": "工作日历",
      "kind": "calendar"
    }
  ]
}
```

## 写入前自检

- `start`、`end` 都是 13 位毫秒，换算回来时间正确
- 地点、会议链接、参会人分别写进字段
- 没有编造参会人
