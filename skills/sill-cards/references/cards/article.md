# article：文章

保存值得以后读的网页文章、博客、资讯和阅读器条目。自己的想法、记录或引文用 [note](note.md)。

示例是合成资料，只展示 `sill_createContent` 参数里外层的 `body` 对象，不能当作用户资料保存。通用要求见[类型索引](../types.md)，字段格式见[字段字典](../fields.md)。

## 显示

卡面：封面 → 来源行（发布方或作者、日期、阅读进度）→ 标题 → 摘要。详情：来源、标题、封面、正文，可放大阅读；正文的 `##` 小标题生成目录。

## 填写清单

| 字段 | 要求 | 怎么写 |
| --- | --- | --- |
| `title` | 必填 | 用原文标题；原标题是「标题党」或只有站名时，改写成说清主题的一句话 |
| `summary` | 必写 | 1–2 句、60–100 字：这篇讲了什么，结论或亮点是什么。不写「本文介绍了」 |
| `body` | 必填 | 完整原文 Markdown，删掉广告和页面杂项，见[导入细节](../import.md#正文完整与清理) |
| `url` | 有就写 | 原文地址 |
| `authors` | 有就写 | 发布方在前、作者在后，来源行按顺序显示 |
| `publishedAt` | 有就写 | 原文发布日期；有时刻就写带时区 ISO 时间 |
| `images` | 有就写 | 原文封面的 HTTPS 地址，第一张作封面 |
| `tags` | 建议 | 2–4 个主题词，用用户已有的标签优先 |
| `sources` | 必写 | 内容从哪来，例如 `{name:"庭院观察网站",kind:"web"}` |

## 写法

标题说主题，摘要说结论。卡面不显示正文，用户只靠这两行决定读不读。

正文结构：

```markdown
## 原文第一个小标题

原文段落……

## 原文第二个小标题

- 原文列表

> 原文引用
```

按原文层级写。原文没有小标题时不要自己加；原文里的图片只留替代文字，封面写进 `images`。

## 示例

```json
{
  "type": "article",
  "title": "小庭院也能收集雨水：三步搭起一套低成本系统",
  "summary": "作者在 20 平方米的庭院里用一个周末搭好雨水收集，讲清选桶、接管、过滤三步，第一年省下约三成浇水用量。",
  "url": "https://example.com/garden/rainwater",
  "authors": [
    {
      "name": "庭院观察"
    },
    {
      "name": "林青"
    }
  ],
  "publishedAt": "2026-10-20T08:30:00+08:00",
  "images": [
    "https://example.com/garden/rainwater-cover.jpg"
  ],
  "tags": [
    "庭院",
    "雨水"
  ],
  "body": "## 为什么要收集雨水\n\n我家庭院只有 20 平方米，夏天每周要浇三次水。屋顶每年接到的雨水，远比花园用掉的多。\n\n## 第一步：选桶\n\n选 200 升带盖的食品级储水桶，深色桶身能减少藻类。\n\n- 桶底垫高 30 厘米，方便接水龙头\n- 留出溢流口，接回排水沟\n\n## 第二步：接管\n\n在落水管离地 1 米处装分流器，雨水先进桶，满了再走原来的管道。\n\n## 第三步：过滤\n\n分流器自带滤网，每月清一次落叶就够了。\n\n> 雨水不经处理不能饮用，只用来浇花和洗工具。\n\n## 第一年的结果\n\n1. 浇水用量少了约三成\n2. 夏季连续晴天超过两周时，储水会用完",
  "sources": [
    {
      "name": "庭院观察网站",
      "kind": "web"
    }
  ]
}
```

## 写入前自检

- 正文是完整原文，结尾与原文结尾一致
- 广告、关注引导、相关推荐已删除
- `url`、`authors`、`publishedAt`、封面都从来源填了
- 摘要说出了结论，不是标题的重复
