# digest：摘要

把一组资料或一个时段汇总成一张卡：每周阅读、会议纪要合集、调研结论。

示例是合成资料，只展示 `sill_createContent` 参数里外层的 `body` 对象，不能当作用户资料保存。通用要求见[类型索引](../types.md)，字段格式见[字段字典](../fields.md)。

## 显示

卡面：来源行（关联卡数）→ 标题 → 摘要。详情：正文和引用卡（`related`）。

## 填写清单

| 字段 | 要求 | 怎么写 |
| --- | --- | --- |
| `title` | 必填 | 汇总的范围和结论，例如「本周 6 篇雨水收集文章的共识」 |
| `summary` | 必写 | 最重要的结论，一两句；卡面只显示它 |
| `body` | 必填 | 分小标题写结论、分歧、待办 |
| `related` | 有就写 | 被汇总的 Sill 卡片 ID，先读到真实 ID 再写 |
| `sources` | 必写 | 助手整理写 `agent` |

## 写法

摘要卡写结论，不是目录；每条结论说清出自哪张卡。

正文结构：

```markdown
## 结论

- 结论（出自哪张卡）

## 分歧

- 不同说法

## 下一步

- 建议做的事
```

## 示例

```json
{
  "type": "digest",
  "title": "本周雨水收集资料的三个共识",
  "summary": "5 份资料都建议先装分流器再选桶；储水桶要遮光；冬季前必须排空。",
  "body": "## 结论\n\n- 先装分流器，再按屋顶面积选桶（文章、视频都这样建议）\n- 储水桶放背阴处或选深色桶，减少藻类\n- 气温低于 0 度前排空水管\n\n## 分歧\n\n- 是否需要二级过滤：播客认为浇花不需要，文章建议加装\n\n## 下一步\n\n- 量一下屋顶面积，再决定买 200 升还是 300 升的桶",
  "tags": [
    "雨水"
  ],
  "sources": [
    {
      "name": "助手整理",
      "kind": "agent"
    }
  ]
}
```

## 写入前自检

- 摘要是结论，不是「本周汇总了 5 篇文章」
- `related` 只写真实读到的卡片 ID
