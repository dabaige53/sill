# mail：邮件

留存一封值得以后查的邮件。邮件里有要办的事时，另建一张 [task](task.md) 或 [reminder](reminder.md)。

示例是合成资料，只展示 `sill_createContent` 参数里外层的 `body` 对象，不能当作用户资料保存。通用要求见[类型索引](../types.md)，字段格式见[字段字典](../fields.md)。

## 显示

卡面：发件人（第一个 `authors`）→ 主题 → 摘要，不显示附件。详情：发件人、主题、正文、全部附件。不显示收件人。

## 填写清单

| 字段 | 要求 | 怎么写 |
| --- | --- | --- |
| `title` | 必填 | 邮件主题 |
| `summary` | 必写 | 一句话说这封信要你知道或做什么，有截止时间写出来 |
| `authors` | 必填 | 第一项是发件人 |
| `publishedAt` | 必填 | 发送时刻，带时区 ISO 时间 |
| `body` | 必填 | 邮件正文全文，删掉签名档里的广告、免责声明模板和历史引用 |
| `files` | 有就写 | 附件：名称、MIME、字节数、HTTPS 链接 |
| `sources` | 必写 | `{name:"工作邮箱",kind:"mail"}` |

## 写法

主题是「Re: Re: 关于」这类时，可以改写成说清主题的一句话。

正文结构：

```markdown
称呼，

正文段落……

需要确认：
- 事项
```

保留原信的段落和列表；转发链只留与本事相关的那一封。

## 示例

```json
{
  "type": "mail",
  "title": "周五评审材料请提前阅读",
  "summary": "林青请你在周五 14:00 评审前看完附件，并确认范围和验收条件两项。",
  "authors": [
    {
      "name": "林青"
    }
  ],
  "publishedAt": "2026-10-30T09:12:00+08:00",
  "body": "你好，\n\n周五下午的产品评审材料已经整理好，请在会前阅读附件。\n\n需要你确认：\n- 本轮范围是否包含导出功能\n- 验收条件是否需要补充示例\n\n有问题直接回复这封邮件。\n\n林青",
  "files": [
    {
      "name": "产品评审材料.pdf",
      "url": "https://example.com/files/review.pdf",
      "mimeType": "application/pdf",
      "sizeBytes": 482304
    }
  ],
  "sources": [
    {
      "name": "工作邮箱",
      "kind": "mail"
    }
  ]
}
```

## 写入前自检

- 发件人和发送时刻都写进字段
- 附件写进 `files`，没有写成正文里的链接列表
- 要办的事另建了待办或提醒
