# 界面对账表

更新：2026-10-23。基准：本文件最近一次提交（`git log -1 -- docs/product/ui-alignment.md`），Web 与 Mac 在同一提交中。

本表记录 Web 桌面、手机 Web 与 Mac 在每项界面行为上的当前状态。Mac 的视觉、状态与动效以 Web 和设计手册为准；本表回答「Mac 跟到了哪里」「哪些差异是刻意的」「哪些还没在真实窗口看过」。

- 本表记录现状。检查方法与每次 PR 的结果格式见[跨端对齐检查清单](../guides/cross-platform-checklist.md)。
- 产品能力（登录、MCP、云端）见[功能矩阵](feature-matrix.md)，本表只记界面与交互。
- 2026-10-20 的[逐行清单](../records/2026-10-20-macos-web-alignment/rule-checklist.md)是重建 Mac 界面时的记录，按手册行号对应，现已错位，只作历史参考，由本表替代。

## 自动同步，不逐项对账

放大页排版依据 [ADR 0065](../adr/0065-expanded-reading-layout.md) 与[探索画布](../../design-system/boards/expanded-reading.html)。Web、Mac 接入资讯与媒体放大布局：预览保留底部操作，放大操作位于左上角；视频 1.6:1、播客等宽分栏，窄屏上下排列；资讯目录来自真实 Markdown 标题，可收起，当前位置蓝色加粗，普通项灰色。手机 Web 保留预览底部胶囊，并提供可展开的目录。展开与收起使用 expandedSpring，正文不缩放，工具不跨页面移动。原生 iOS 只有数据层，阅读界面缺失。本次未部署，真实窗口和真机仍为未验证。新增动效沿用项目规则，不增加 reduceMotion 分支。

以下内容由同一份源文件生成或读取，两端不各自维护数值。改动后运行 `npm run contracts:generate`。

| 内容 | 源文件 | Web | Mac |
| --- | --- | --- | --- |
| 颜色、字号、间距、圆角、动效时长与曲线 | `design-system/tokens/*.json` | `apps/web/styles/tokens.css` 与 `tokens.motion` | 生成的 `AppleMetrics`、`AppleColors` |
| 界面文案 | `design-system/copy/zh-Hans/*.json` | `copy("…")` | `Copy.text("…")`，使用同一键名 |
| 图标 | Mono24 SVG | `Icon` | `Icon`，读取同一批 SVG |

变量相同不等于行为相同。行为仍按下表逐项对账。

## 状态写法

**代码列**（Web 桌面、手机 Web、Mac）：

| 写法 | 含义 |
| --- | --- |
| 基准 | Web 实现即参照，规则以手册为准 |
| 已接入 | 代码已实现手册规则，并通过非界面检查 |
| 缺失 | 手册要求，代码没有 |
| 刻意不同 | 平台差异，说明列写依据（ADR 或手册条目） |
| 不适用 | 该端没有这个场景，说明列写原因 |
| 待澄清 | 手册与代码不一致，或两端都没做，需要决定 |
| 未核对 | 本表建立时没有核对代码 |

**实测列**：只记录真实窗口或真机中看过的结果。

| 写法 | 含义 |
| --- | --- |
| 未验证 | 没人在真实窗口看过；自动测试和构建通过不算 |
| 待确认（日期） | 用户在该日期反馈过问题，已修复，等用户在真实窗口确认 |
| 通过（日期，端） | 用户或获授权的检查在真实窗口确认 |
| 有问题（日期） | 已知问题，说明列写现象 |

## 更新规则

1. 改动任一端界面、交互或动效的提交，同时更新本表受影响的行和文首日期。提交不能写入自己的编号，基准以本文件最近一次提交为准。
2. Web 先改、Mac 没有跟进时，在 Mac 列写「缺失」并在「待处理」登记，不能留空或沿用旧状态。
3. 两端都改时，代码列写「已接入」；实测列保持「未验证」，直到有人在真实窗口看过。用户反馈的问题修复后写「待确认（日期）」。
4. 新增平台差异必须在说明列引用 ADR 或手册条目；只写「平台不同」不算依据。
5. 新增行为时按区块追加编号，不重排已有编号。行为删除时保留编号并写「已删除」及日期。
6. 手册改动导致某行依据变化时，同一次提交更新该行。
