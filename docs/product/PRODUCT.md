## Platform

web

Web/PWA 是此产品上下文的界面基准。macOS 使用 SwiftUI，共用产品规则并保留平台适配；iOS 当前只有共享数据层，不视为已交付的原生界面。各端差异见 [界面对账表](ui-alignment.md)。

## Users

主要用户是已使用外部 AI 助手的个人用户。他们让助手整理内容，在 Sill 中阅读卡片、查看待办与日程、完成轻操作。

## 1. 产品是什么

一个由 Agent 驱动的个人卡片工作台。文章、邮件、笔记、待办、日程、提醒、媒体、照片、文件、摘要、建议和 PR 以卡片呈现，按「现在该看什么」组织。用户主要做两件事：往下翻，点开读。

产品的分工是助手整理内容、用户阅读与表达意图、卡片呈现真实状态。使用效果以用户能找到当前需要的内容、读懂卡片并完成相关轻操作为判断依据。

内容由用户自己的外部助手整理，通过 Sill MCP 写入和修改。Sill 不接入外部来源，不由程序同步内容；Web/PWA 与 Mac 已取消「记一笔」手动记录入口，保留阅读、收藏、任务勾选等轻操作。所有产品数据与状态操作都应能通过 Sill MCP 完成。界面不提供复杂内容编辑器，也不因 Agent 优先而删改其他原有产品设计与轻操作。分工见 [Agent 优先与界面边界](agent-mcp.md#agent-优先与界面边界)。

页面负责展示状态和表达意图；完成、阅读也是 agent 可处理的输入，不能把用户点击等同于外部执行成功。外部助手用自己宿主的工具执行，并通过 Sill MCP 回写真实结果；仅涉及本地阅读偏好的意图可以本地确认，无需制造外部写入。

当前已有本地 Web 与 CLI、鉴权云端网页、卡片 API 和内容／工作区 MCP；Mac 源码已接入云端，保留独立本地测试模式。具体实现与验证状态见 [功能矩阵](feature-matrix.md)。

V1 目标是外部助手 Webhook → Sill MCP 回写，Webhook 与可靠执行器尚未实现。内置助手及 Composio 连接器是远期可选方案，不作为 V1 前置条件；详见 [远期执行与能力边界](agent-execution.md#内置助手与委托形态远期可选尚未实现)。

## 2. 视觉原则

1. 内容以卡片为中心，页面入口按桌面与手机的使用方式安排。
2. 安静、可读优先。卡片使用实底，玻璃用于浮动操作区。
3. 颜色表达状态；已读卡片变淡但仍可读。
4. 普通控件只用文字或只用图标；导航等已确认例外遵循设计手册。
5. 桌面和手机使用相同的状态与操作含义，布局和触发方式按平台处理。

颜色、字体、间距、图标和动效统一见 [设计手册](../../design-system/README.md)。

## 3. 页面

| 场景 | 职责 |
| --- | --- |
| 首次使用与新增 | 按本地或云端入口进入，由助手通过 MCP 创建卡片 |
| 主页 | 阅读信息流、分栏、排序与轻操作 |
| 详情与阅读 | 阅读完整内容、查看关联信息、播放支持的媒体 |
| 搜索与归档 | 查找卡片、查看归档与放回主页 |
| 设置与 AI 入口 | 管理偏好；内置 AI 未接入时只展示已有占位能力 |

桌面与手机的导航、搜索、设置和 AI 入口见 [交互规范入口](interaction-spec.md)。现行画板位置见 [设计系统映射](../design/system.md#画板)。来源接入、RSS/OPML 订阅与文件导入不属于产品范围。

## 4. 卡片

类型：文章、邮件、笔记、待办、日程、提醒、媒体（播客、视频）、照片、文件、摘要、建议、PR。收藏、稍后读、已读、标签、备注是跨类型的状态，不另做卡片。

卡面用标题、摘要、来源与必要的专属字段帮助用户判断；详情文字统一写入 Markdown body，要点放在正文列表。任务、日程、附件、章节、文字稿和 PR 快照保留各自结构。字段含义与上限见 [跨端数据约定](../../contracts/README.md)，写作规则见 [卡片内容设计规范](../design/card-content.md)。

标题、摘要的显示行数与截断规则按卡片类型和平台处理，统一见 [字体](../../design-system/handbook/foundation.md#字体)与[文字长度](../../design-system/handbook/foundation.md#文字长度)。详情保留完整正文。

## 5. 信息流

- 按重要和时间排序：快到时间的提醒（15 分钟内）和日程（30 分钟内）自动上浮。
- 同一来源短时间内的多张卡叠成一摞，可左右切换，单击展开。
- 一次显示 40 张，滑到底继续加载。
- 刷新不强制回到顶部；新内容先提示，点了再插入。
- 读过的卡片可以按设置变淡、到期收起；同一提醒不反复出现。

## 6. 来源

- Sill 不接入外部来源，也不由程序同步内容。不做 RSS/OPML 订阅，不连接 Readwise、邮件、日历、GitHub 等来源，不做文件导入或 Markdown 导入。
- 卡片内容由助手写入：外部助手整理好内容后，通过 Sill MCP 写入和修改卡片。界面保留阅读与轻操作，不提供速记入口或复杂内容编辑器。
- 卡片的来源字段只记录内容来自哪里（例如某个邮箱、某个日历或写入它的助手），用于显示和叠卡，不表示 Sill 已连接该来源。
- 用户不想看某类内容时，用卡片菜单的「少看这类」「不再提示」表达意图，由助手调整之后写入的内容。
- 连接器只用 Composio，只供远期的内置助手操作其他程序。其他外部工作交给外部助手，用它自己宿主的工具完成。

## 7. 阅读

- 单击卡片打开详情，支持完整阅读的类型可进入放大阅读。
- 桌面与手机的打开、关闭和返回方式见 [预览与叠放](../../design-system/handbook/interaction.md#预览与叠放)。
- 打开过不等于读完；阅读完成、短文计时与关闭手势按 [两端共用规则](../../design-system/handbook/interaction.md#两端共用)和[提交、取消与导航](../../design-system/handbook/motion.md#提交取消与导航)处理。
- 视频与播客只根据真实播放状态保存位置；实际播放结束才自动标为已读，拖到结尾不算完成。
- 跳出到来源网站需要用户明确操作。

## 8. 轻操作

- 卡片 •••：收藏、稍后读、标签、备注、标为已读、少看这类等。
- 多选操作与卡片拖入 AI 区域使用已有入口；具体行为见 [交互规范入口](interaction-spec.md#卡片)。拖入仅提供上下文，不因拖动自动发送或执行外部动作。
- 待办可勾选完成，提醒可完成、延后、忽略。
- 阅读、收藏和任务勾选更新 Sill 状态。外部动作的待处理、执行中与完成属于待实现的执行流程；只有取得可信回执后才能表达外部完成。
- 未派发意图可取消；已派发动作的取消不保证外部撤销。外部撤销若受支持，应成为新的补偿意图，不能承诺所有动作可逆。
- 重复点击不得重复创建外部对象；超时且结果未知时先核对，不盲目重试。目标状态协议见 [Agent 与 MCP](agent-mcp.md)。

## 9. 设置

设置保留桌面偏好、外观、快捷键、数据与隐私等轻操作，不恢复已取消的手动新增入口。桌面弹窗与手机页面的分组、位置和可用状态见 [设置规则](../../design-system/handbook/web-interaction.md#设置弹窗)与[现行设置画板](../../design-system/README.md#设置)。

## 10. 数据与边界

- 本地 Web 与 CLI 共用本机 JSON；云端网页与 MCP 按账号读写云端工作区。Mac 源码默认连接云端，独立本地测试模式不自动上传旧数据。
- 已有内容由助手读写；保存携带版本或原始字段条件，批量操作全部成功才保存。数据格式与冲突规则见 [本地操作](../guides/local-operations.md)和[接口与交接包](../guides/handoff.md)。
- 当前没有内置助手。卡片详情可将当前卡片引用交给支持消息的外部宿主；独立页面不显示该入口。交接不表示内容已修改或任务已执行。
- 外部助手使用自己宿主的工具处理外部动作。远期内置助手只使用 Composio 连接器；上游授权与秘密留在对应安全配置中。
- 定时或事件驱动执行取决于实际宿主能力；浏览器关闭后的自动执行不是当前已有能力。

## 11. 可访问性

全部操作可用键盘完成；手机触控区域不小于 44px；支持深色主题，不提供专门的无障碍设置或系统偏好适配；纯图标控件都有可访问名称。
