# 跨端对齐检查清单

更新：2026-10-27。用于界面修改、跨端审查和交付检查。本文规定检查项目，不记录当前产品已通过哪些项目；各端当前状态记在[界面对账表](../implementation/design/ui-alignment.md)；检查结果按第 5 步写入 PR 或事件记录，实现发生变化时更新该表。历史对齐记录不能作为当前通过证据。

## 使用方法

1. 明确本次功能、改动端、关联端，以及 Web 本地、云端或 MCP 宿主运行路径。本文的「手机」指手机 Web/PWA，不表示原生 iOS 已实现。
2. 从下表选择受影响项目及直接关联项目，列出编号。完整对齐审查须逐项记录；局部修改只检查相关项，未选项写为本次未检查。
3. 读取该项的现行依据，记录代码位置和两端结果。关联端检查不自动授权修改关联端。
4. 按 [测试与验证](../agent/test.md) 执行已获授权的检查。没有界面测试授权时，完成代码与非界面检查，视觉列保留「未验证」。
5. 在 PR Evidence 或本次记录中填写结果表，列出未完成项。检查标准变化时更新本文和现行设计依据；历史记录保持原样。

参数只在 [设计变量](../../design-system/tokens) 维护；文案、尺寸、动画曲线和时长以现行手册及生成变量为准，不在本清单复制数值。依据之间有冲突时，记录具体冲突并标为「待澄清」，不能自行选择一份后判为通过。

## 允许的平台差异

| 项目 | Web 桌面 | macOS | 手机 Web/PWA |
| --- | --- | --- | --- |
| 绘制与材质 | Web 样式与 Motion | SwiftUI/AppKit；系统支持时使用规定的原生玻璃 | 移动 Web 样式与抽屉 |
| 详情打开 | 来源卡片空间过渡 | 来源卡片空间过渡 | 手机抽屉；不要求复制桌面展开 |
| 详情下拉关闭 | 不启用 | 不启用 | 保留 |
| 导航与搜索 | 桌面顶栏与卡片区搜索 | 桌面结构及原生快捷键 | 独立页面与底部导航 |
| 更多菜单 | 分栏菜单与轻操作条 | 保留原生端规定的卡片右键入口，差异单列 | 轻操作与多选操作条 |
| 宿主能力 | 区分独立网页与 MCP 宿主协商能力 | 以功能矩阵为准 | 区分普通网页、PWA 与宿主 |
| 系统专有行为 | 浏览器历史与窗口行为 | 窗口控制、菜单栏与本机性能追踪 | 软键盘、安全区与主屏幕启动 |

相同的是内容、动作含义、状态及交互结果，不要求两端使用相同技术实现。新增差异须引用用户确认的决定或现行设计依据，不能仅以「平台不同」作为通过理由。

## 每次检查的结果格式

在本次 PR 或记录中使用以下字段，不在本文件累计运行结果：

| 项目编号 | 端与运行路径 | 代码位置及版本 | 代码接入 | 行为检查 | 视觉确认 | 证据或问题 | 差异依据 |
| --- | --- | --- | --- | --- | --- | --- | --- |

- 同一编号按端分别填写。代码接入填写「已接入／缺失／待澄清」；行为与视觉填写「通过／失败／未验证／不适用」。不适用必须有平台依据。
- 行为证据记录命令、结果与对应代码版本；视觉证据记录观察方式、日期、窗口尺寸、主题及数据场景。用户反馈可作证据，但只覆盖实际反馈的端和场景。
- 自动检查只能证明其覆盖的断言。构建、lint、参数相同或后台性能测试通过，不能填为视觉确认通过。
- 本次范围内的适用项全部有结果，且失败、缺失、待澄清和未验证项已列明，才算检查记录完成。只有所需行为与视觉证据都通过，才能宣称该项对齐验收通过。
