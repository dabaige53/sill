# 审计问题修复

本轮修复仓库审计确认的 7 项问题。代码已在本地验证；没有应用线上数据库迁移或发布应用。

## 修改结果

| 审计项 | 修复后的行为 |
| --- | --- |
| 首次保存阻塞 | 工作区读取补齐播放位置和排版默认值，Web 首次保存可通过原始值检查，后续收藏等修改继续保存。 |
| 批量校验内存 | Zod 升至 4.6.6，超过操作数量上限时先拒绝整个数组，不再为每个元素建立错误。 |
| Mac 旧进度覆盖 | 延迟记录保留原进度基准；刷新改变基准时舍弃旧记录。保存使用界面已经应用的版本，排队的后台记录不借用前台写入后的新版本。 |
| 整卡替换残留 | `card.upsert` 清除省略的已知字段，保留未知扩展和个人状态；Mac 的未知结果核对使用相同规则。 |
| Mac 阅读秒数丢失 | 确定未写入的失败保留秒数，结果未知时仍先读取核对。连续关闭或失焦不会同时取走同一份待保存记录。 |
| Markdown 解析耗时 | markdown-it 升至 14.3.3，补充未闭合多行引用的 CPU 耗时回归。 |
| 过期回执占用 | 读取工作区或检查会话时，按账号清空过期回执的完整响应；保留请求摘要和原键，过期请求仍拒绝重放。 |

依赖升级后保留 PR 观察时间的分钟精度和原文本。MCP 对该字段按 ISO 时间模式校验，不再错误声明为必须包含秒的 RFC 3339 格式；服务端生成的创建、更新时间继续使用 RFC 3339。

全仓 `npm run lint:web` 未通过，报告 32 个错误，位置不在本轮修复文件。没有扩大为全仓格式修改。

`npm audit --omit=dev` 不再报告 Zod 和 markdown-it 的原漏洞，仍报告 8 项其他依赖告警；这些告警未在本轮确认为可触发缺陷。

同一本机合成输入中，约 300 KB 的非法批次从 100001 条错误、约 109 MiB 额外堆内存，降至 1 条错误、约 1 MiB。约 300 KB 的未闭合 Markdown 引用从约 1.9 秒降至约 0.48 秒。这是本机单次复现，不代表浏览器或设备性能验收。
