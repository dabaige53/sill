# 手机抽屉打开结束闪一下

**状态：已修复待验证。最近检查：2026-10-29。**

## 环境与触发

iPhone 主屏幕 Web App，本地服务（局域网地址），工作区含未提交的手机搜索与加载动画改动。主页点开日程卡，卡片以 Vaul 抽屉从底部升起，抽屉后方主页底部的卡片闪一下；用户补充：第一次打开会闪，第二次打开不闪。预期打开过程中主页卡片不变。

## 定位依据

用户提供 Safari 时间线录制（含登录信息，未入库，只读取事件类型、时间和绘制区域）：

- 点击后约 80ms 抽屉开始升起；约 600ms 后，抽屉滑入与遮罩淡入两段 CSS 动画同时结束，Vaul 的 0.5s 计时器同时触发。
- 结束时刻没有页面脚本修改 DOM（MutationObserver 无回调），但出现整屏绘制、抽屉两块图块及底部工具栏区域重绘；约 125ms 后再有一次整屏绘制。
- 截图约每 100ms 一帧，没有拍到闪的那一帧。

推测（未证实）：抽屉带 Vaul 的 `will-change: transform`，结束后仍保留独立图层；遮罩 `.phone-drawer-overlay` 只在淡入期间合成，结束后并回页面，抽屉与工具栏随重叠关系重绘，形成一帧闪烁。与[桌面云端闪屏](README.md#闪屏诊断)不同：本次无保存回执触发的详情重建。

## 处理情况

[phone-overrides.css](../../../apps/web/styles/phone-overrides.css) 为遮罩加 `will-change: opacity`，使其在动画结束后保留图层。未改动画、时长与抽屉结构。

## 当前判断

主页封面为懒加载，[ADR 0089](../../../docs/adr/0089-steady-content-arrival.md) 起新加载封面一律淡入 420ms。打开抽屉时页面缩小并冻结位置，下方尚未加载的封面进入加载范围，在抽屉后逐张淡入；第二次打开时这些封面已加载，直接显示。这与「第一次闪、第二次不闪」和「闪的是底部卡片」一致，但未在真机逐帧证实。

处理：[app-feed.ts](../../../apps/web/views/app-feed.ts) 只让屏幕内、页面未被抽屉盖住时加载的封面淡入；屏幕外和抽屉下方加载的封面直接显示。回归测试见 [app-display.test.ts](../../../tests/web/app-display.test.ts)。遮罩图层改动保留，未证实有效也未发现副作用。

## 排除

- 第一次打开会写入 seen 并保存到本地服务。用隔离数据模拟「本地保存 → 回执 → adopt」，第一次和第二次打开都没有触发主页重绘或详情替换，因此不是本地版的保存回执问题。
- 手指点按时 `data-input-modality` 为 pointer，卡片 `focus-within` 样式不生效，排除焦点样式。

## 验证与后续

遮罩图层改动后真机第一次打开仍闪。封面改动随 1.2.10–1.2.12 提交；按当前代码重新构建，并以新端口（新来源、无旧缓存）在真机测试，打开卡片时底部仍闪。封面淡入不是原因，或不是唯一原因。

用户进一步观察：闪的是底部导航胶囊（主页、对话、搜索）所在区域。录制中屏幕底部约 114px 条带（胶囊所在）恰在打开开始、关闭结束两个时刻重绘，即整页开始和停止缩放的帧。导航胶囊在页面容器内、保留实时毛玻璃（phone-overrides.css 有意排除它，因为改成平面会在一帧内变色）；页面其余毛玻璃在抽屉期间已压平。推测（未证实）：整页加上或去掉缩放时，iOS 重建胶囊的毛玻璃，一帧内胶囊显示不正常。

处理（用户决定）：手机底部胶囊不再使用实时毛玻璃，改为 `glass-thick` 底色，见 [phone-overrides.css](../../../apps/web/styles/phone-overrides.css) 末尾；原玻璃规则保留，删除该覆盖即可恢复。同一原因也解释了「底部栏上滑恢复时颜色最后一帧突变」：淡入作用在 `#dock` 外层，外层半透明期间内部胶囊的模糊取不到页面，结束时突然生效。桌面底部只有自带玻璃外形的组件，没有额外的模糊层，不改。

胶囊改为实底后真机仍闪。临时对照构建关闭打开时的页面冻结与缩放，仍闪，排除页面冻结。

## 逐帧定位（iPhone 系统录屏，60 帧）

用户从录屏中截出关键帧：抽屉升起的前几帧（约 4 帧，70ms），抽屉上半截有白底，下半截的正文直接画在主页卡片上方，随后白底补齐。抽屉位置正确，是白底晚于文字出现。同时录屏显示抽屉一出现就已接近终点，前段滑入没有出帧，说明第一次打开的前几帧绘制繁忙。

用户补充：所有卡片类型打开时都如此，不限文章。

原因判断：手机抽屉是一整块大图层，第一次打开时 iOS 分块绘制赶不上滑入动画，下半截的图块晚几帧到。正文滚动区（`.sheet-scroll`）单独成层且按时画出，但本身没有底色，所以出现「有字无底」；底部工具条去掉毛玻璃后并入抽屉大图层，同样晚到。Vaul 的拖过头补色伪元素（此处已透明，不画任何内容）向下延伸两倍高度，把抽屉图层撑到约三倍。所有卡片共用 `phone-drawer → preview-sheet → sheet-scroll` 结构，因此都受影响；第二次打开图层已画过，不闪。

处理（作用于共用抽屉，[phone-overrides.css](../../../apps/web/styles/phone-overrides.css)）：

- 正文滚动区继承所在 sheet 的底色与圆角，文字与底色同层出现。
- 底部工具条单独成层，不再随抽屉大图层晚到。
- 去掉 Vaul 的透明延伸伪元素，抽屉图层缩回实际高度。

已构建，待真机验证。

此前仍未排除的方向（供复发时参考）：打开时 Vaul 缩放整页（transform、圆角裁切），录制显示升起开始时整页卡片全部重绘，下方图块可能晚一帧画出；第一次与第二次打开走不同路径（第二次可能复用保留的详情）。下一步：iPhone 系统录屏（60 帧）逐帧确认闪的位置和时刻；或做临时对照构建，关闭背景缩放，看闪烁是否消失。
