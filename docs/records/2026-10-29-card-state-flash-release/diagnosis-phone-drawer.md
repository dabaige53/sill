# 手机抽屉打开结束闪一下

**状态：已修复待验证。最近检查：2026-10-29。**

## 环境与触发

iPhone 主屏幕 Web App，本地服务（局域网地址），工作区含未提交的手机搜索与加载动画改动。主页点开日程卡，卡片以 Vaul 抽屉从底部升起，抽屉后方主页底部的卡片闪一下；用户补充：第一次打开会闪，第二次打开不闪。预期打开过程中主页卡片不变。

## 定位依据

用户提供 Safari 时间线录制（含登录信息，未入库，只读取事件类型、时间和绘制区域）：

- 点击后约 80ms 抽屉开始升起；约 600ms 后，抽屉滑入与遮罩淡入两段 CSS 动画同时结束，Vaul 的 0.5s 计时器同时触发。
- 结束时刻没有页面脚本修改 DOM（MutationObserver 无回调），但出现整屏绘制、抽屉两块图块及底部工具栏区域重绘；约 125ms 后再有一次整屏绘制。
- 截图约每 100ms 一帧，没有拍到闪的那一帧。

推测（未证实）：抽屉带 Vaul 的 `will-change: transform`，结束后仍保留独立图层；遮罩 `.phone-drawer-overlay` 只在淡入期间合成，结束后并回页面，抽屉与工具栏随重叠关系重绘，形成一帧闪烁。与[桌面云端闪屏](README.md#闪屏诊断)不同：本次无保存回执触发的详情重建。

## 处理情况

[phone-overrides.css](../../../apps/web/styles/phone-overrides.css) 为遮罩加 `will-change: opacity`，使其在动画结束后保留图层。未改动画、时长与抽屉结构。

## 当前判断

主页封面为懒加载，[ADR 0089](../../../docs/adr/0089-steady-content-arrival.md) 起新加载封面一律淡入 420ms。打开抽屉时页面缩小并冻结位置，下方尚未加载的封面进入加载范围，在抽屉后逐张淡入；第二次打开时这些封面已加载，直接显示。这与「第一次闪、第二次不闪」和「闪的是底部卡片」一致，但未在真机逐帧证实。

处理：[app-feed.ts](../../../apps/web/views/app-feed.ts) 只让屏幕内、页面未被抽屉盖住时加载的封面淡入；屏幕外和抽屉下方加载的封面直接显示。回归测试见 [app-display.test.ts](../../../tests/web/app-display.test.ts)。遮罩图层改动保留，未证实有效也未发现副作用。

## 排除

- 第一次打开会写入 seen 并保存到本地服务。用隔离数据模拟「本地保存 → 回执 → adopt」，第一次和第二次打开都没有触发主页重绘或详情替换，因此不是本地版的保存回执问题。
- 手指点按时 `data-input-modality` 为 pointer，卡片 `focus-within` 样式不生效，排除焦点样式。

## 验证与后续

遮罩图层改动后真机第一次打开仍闪。封面改动后需在真机重开 App、第一次打开卡片确认；若仍闪，用 iPhone 系统录屏（60 帧）逐帧确认闪的卡片和时刻，并区分「每张卡第一次」与「重开 App 后第一次」。
