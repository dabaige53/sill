# 发布产品仅使用云端数据

日期：2026-10-29。状态：源码已修改，等待 GitHub 检查。

## 原因与处理

云端空白页的 welcome-demo 动作调用 loadDemo，将示例卡片插入 Store，再由 CloudSync 写入真实账号。它不是临时预览，没有独立的退出或撤销流程。

删除云端与共用欢迎页的示例按钮、动作和插入方法。空账号保持为空，登录及连接重试入口保留。已有账号卡片不自动删除。

Mac 发布版固定使用云端启动配置，不再读取 --data-directory 参数。Debug 保留隔离测试入口。云端 Web 原本使用内存状态和服务器接口，没有改用浏览器本地存储的路径。

WebDAV 和 R2 仅用于备份。用户明确将定时备份留待后续任务，本次保留手动备份与恢复，不新增同步来源。

## 验证

更新云端浏览器回归，检查空账号没有示例入口，刷新后服务器卡片仍为空。增加 Mac Release 启动配置检查。测试与构建交给 GitHub Actions，本地只做文件与差异检查。未执行界面验收，尚未部署本次修改。

## 发布检查发现的关联问题

GitHub 云端操作回归在批量保存标签时报 revision_conflict。保存回执的可见内容比较忽略了元数据变化，但 adoptWorkspace 也因此跳过 Store 卡片投影更新。后续写入把旧 updated_at 派生的 time 当作真实字段，读取基准与服务器不一致。

改为每次接收回执都更新卡片投影，只在可见内容变化时重绘。已有云端回归先切换任务、收藏和稍后读，再批量写标签和备注，覆盖该失败路径。另修正 GitHub 报告的导入顺序、格式和表达式内赋值问题。
