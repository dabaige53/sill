# 手机 PWA 极端条件检查

检查日期：2026-10-23。基准：`6dfc916`，Sill 1.2.7 的本地 Web 构建。

结论：确认 7 项缺陷。详情滚动扩展会瞬间改变位置；内部布局存在超宽、裁切和额外留白。已测场景的页面总宽度等于视口宽度，尚未复现整个页面被撑宽。不建议用全局 `overflow-x: hidden` 掩盖内部问题。

本次仅新增诊断样本、预览工具和记录，未修改产品实现、实际卡片或线上环境。

## 动画审查

| 现状 | 建议 | 原因 |
| --- | --- | --- |
| 正文开始滚动就立即从预览高度跳到全屏高度 | 记录展开意图；在合适的手势结束点确定高度；通过 transform 补偿当前位置，沿用现有 Motion 控制器接续 | 已量到额外 64px 的瞬间上移，阅读位置不连续 |
| 封面、正文尺寸变化后，`placeHead` 读尺寸、写样式，再读位置 | 集中读几何信息，再统一写入；值相同则不写 | `apps/web/views/preview-controller.ts:129-158` 有同步重算布局的风险；未测得真机掉帧，不能把风险当实测结论 |
| reader 右滑关闭只排除表单和工具条 | 先识别横向滚动内容和交互控件的手势归属 | `apps/web/interactions/gesture-surfaces.ts:124-164` 缺少横向内容判断；本次未进入该路径验证，独立 PWA 预览也不直接提供全屏按钮，列为后续特定路径检查 |

体验阻断：第 1 项已复现，当前动效审查结论为 **Block（未通过）**。修复应先恢复位置连续性，再检查真实设备性能。不因 skill 的通用建议改写项目统一 Motion、现有键盘规则和系统偏好策略。

## 数据边界与覆盖

样本经 `contracts/card.ts` 的 `Card.parse` 校验；长值使用合理的人名、邮箱、文件名、代码路径和会议码，没有随机超长乱码。封面使用项目内置 SVG，链接使用 `example.com`，不打开外部来源。

界面覆盖：主页卡片、全部 13 种展示形态的详情（含视频与播客）、320px 短屏设置与外观分组、搜索输入和筛选区、844×390 横屏主页和日程详情。尺寸包括 320×740、320×568、390×844、430×844、844×390。深浅主题、产品大字号 1.12 倍，以及仅内容字体 2 倍的压力条件已检查；2 倍内容字体不等于完整浏览器缩放，也不等于 iOS 系统字号。

## 已保持正常的项目

- 已测页面根宽度均等于视口，未发现页面整体横向扩张。
- 普通正文的邮箱、长链接可换行；代码块有独立横向滚动。
- 100 项任务详情可渲染，任务文字有换行保护；信息流只显示前三项并保留剩余数量。
- 1,000 张笔记首屏渲染 40 张，不是一次绘制全部；这不代表后续长时间滚动无性能问题。
- 普通文字条件下，390／430px 的邮件、日程、建议、播客、PR 详情没有测到非提示元素的可见溢出。文件卡面仍失败。
- 程序触发 5 轮快速打开、关闭、切换后，最后打开的日程仍保持，只有一个打开的 dialog，未出现旧关闭回调关闭新详情。
- 短屏设置与外观分组未测到可见横向溢出。空列表、单张无正文笔记正常加载。

这些结果只覆盖本次样本，不是全产品通过结论。

## 复现入口与证据

```sh
npm run build
node tests/e2e/pwa-stress-preview.ts
```

打开命令输出的本机地址。工具只监听 `127.0.0.1` 的随机端口，读取构建产物并注入合成浏览器存档，不读取 `.sill/local/`，不提供 API 写入接口。停止进程即可关闭。它是专项诊断工具，不替代产品入口 4318。

页面提供 `Demo data / Worst case / Empty / One / 1,000 rows`、宽度、主题和文字选项。选择保存在 URL；重新加载会重置该隔离来源的合成数据。固定外框只用于并排确认视口宽度，没有修改产品 CSS；200% 选项单独覆盖内容字号。

无控制条的测量入口：`/app?data=worst`；深色大字号：`/app?data=worst&theme=dark&text=large`。预览通过 `navigator.standalone=true` 模拟独立模式分支，没有安装 PWA。

证据：[全部布局测量](measurements.json)、[数据规模](states.json)、[快速开关](rapid-reopen.json)、[展开跳动](scroll-expand.json)、[标题宽度](title-padding.json)。测量中的 `icon-button` 溢出可能来自不可见名称提示，不计为缺陷；工具条缺陷以按钮实际边界单独确认。

工具为应用内 Browser。该环境不支持 CDP `Input.dispatchTouchEvent`，因此展开跳动改用程序滚动复现并明确记录；未声称完成真实触摸取消、惯性、CPU 降速、iPhone 帧率、软键盘、刘海安全区或弱 GPU 验收。Safari 主屏幕真机仍需录制。

## 修复建议顺序与验收

1. 修复详情扩展的视觉锚点、320px 工具条和关联行宽度。快速反向拖动、展开后继续阅读、关闭返回须保持当前位置。
2. 修复会议码、文件名、标签、标题留白。保留信息和既有操作，复查标准与大字号、深浅色及横屏。
3. 真机记录滚动与媒体加载的帧时间。只有录制确认后，再决定是否调整玻璃模糊或更换动画驱动；不全局加 `will-change`。

修复时需同步设计规则与界面对账表；本次没有改变 Web 或 macOS 产品实现，不把 macOS 标为已验证。
