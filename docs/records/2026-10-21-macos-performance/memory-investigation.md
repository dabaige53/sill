# 卡片校验规则重复解析的内存排查

日期：2026-10-21。范围：本地无窗口 Release XCTest。

此前八项基准在同一测试进程运行，XCTest 记录到约 5.23 GB 的测量阶段物理内存峰值。该数字并非 App 日常内存，但不能简单归因于测试框架。

## 原因与修复

产品的 CardValidator.validate 每次校验卡片时，都会将随包固定的 ContractSchema.json 重新解码为 JSONValue。加载 3000 张卡片会重复解析同一份规则 3000 次，造成大量重复分配。现改为进程内惰性初始化并复用不可变的规则；仍对每张卡片执行全部校验，解析错误仍通过原有 throws 路径返回。

单独运行同一 testSearch3000，修复前十次测量中的物理内存峰值为 1374.75 MB，修复后为 84.80 MB，降低 93.8%。单位沿用 XCTest 输出的 kB，以十进制换算。对照指标见 [schema-cache-comparison.json](schema-cache-comparison.json)。这确认重复解析是主要内存来源；未通过堆分析判定永久泄漏，也未测真实 App 窗口占用。

## 验证口径

单项修复前后都执行 3000 张相同合成资讯的四个搜索条件，十次测量。修复修改的是加载校验阶段，不是搜索算法。测量阶段峰值不覆盖加载期间每一个瞬间。计时工具输出的整条 swift 命令进程树峰值会包含编译器，未与 XCTest 指标混用。

修复文件：[CardValidator.swift](../../../apps/apple/SillKit/CardValidator.swift)。

## 整套复验

缓存修复后八项 XCTest 全部通过，十次测量，原始指标见 [schema-cache-suite.json](schema-cache-suite.json)。八项场景各测量区间的最大物理内存值由原记录的 5227.21 MB 降至 104.55 MB，下降约 98.0%。单项与整套进程的分配、回收时机不同，不比较二者的绝对占用；分别与各自修复前场景对照。

共享 CardTests 八项通过，覆盖合法与非法卡片、字段边界、日期时区、兼容读取与迁移。Release 编译通过。真实窗口占用与启动峰值仍需单独追踪，本轮未启动或重启用户 App。
