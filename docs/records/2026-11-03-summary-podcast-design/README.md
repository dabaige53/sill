# 摘要与播客设计画板诊断

检查日期：2026-11-03。状态：设计方案已实施到源码，未做浏览器及 Mac 窗口验收。

## 问题与定位依据

摘要与播客设计画布位于 `design-system/boards/summary-podcast/project/`。交付诊断检查四个 `.dc.html` 和 `canvas.json`，报告 146 条错误：

- 138 条 `Inline style is not allowed`。
- 4 条 `<helmet> is not a valid element name`。
- 4 条 `Attribute "onClick" should be lowercase`。

claude-design 的 Design Component 格式要求用内联样式支持属性编辑，用 `<helmet>` 声明页面基础样式，用 `onClick` 绑定交互。上述错误来自普通 HTML 规则与该格式不一致，未发现需要据此改变布局或交互的依据。仓库的备份设计画板已有相同的格式例外处理，见[备份设计画板诊断](../2026-11-03-backup-design/README.md)。

## 处理情况

四个画板分别声明 `no-inline-style` 文件级格式例外；仅在 `<helmet>` 行声明 `element-name` 例外，仅在四个事件绑定行声明 `attr-case` 例外。注释说明对应画板格式要求，其余 HTML 规则保持启用。未改布局、文案、产品代码或全局检查配置。

用户随后确认手机与 Web 方案，并要求对齐现有纵向间距。选定手机画板与复用它的 Web 画板改用现有 `rhythm-*` 变量；概要头部沿用产品的点击范围及留白补偿，避免 44px 按钮额外撑大上下间距。小节标题到文字为 12px，到自带内边距的列表为 8px；章节行上下内边距改为 12px。Web 画板移除外层额外的 24px 顶部留白，由内容层统一使用 40px，手机保持 24px。备选及当前结构示意保持原样。

## 验证与后续

按完整报告提供的 `recheck.command` 调用 `diagnostics_backend.py`，使用 HTML、JSON language server 及 HTML 校验流程复查。四个画板与 `canvas.json` 全部返回 `status: passed`，各文件 `diagnostics` 均为空。


## 播客源码实施

用户确认按方案修改播客相关代码后，Web 手机封面改为 96，Web 桌面与 Mac 改为 128；尺寸从共享 Apple 变量读取。封面、来源与收听记录同组，标题和标签使用完整行宽，内容列最大宽 720。头部到概要为 24，带标题的正文小节之间为 32；概要沿用共用控件，没有新增文字切换按钮或改变长短摘要状态流程。

简介增加小节标题，文字稿与「节选」并为一行；章节与信息表保留全部已有内容。Mac 同步内容顺序、列宽、白底和顶部 40 的留白，并按同一位置调整关闭按钮。两端仍只读取外部收听记录，不增加播放器、章节跳转或状态写入。

已补充 Web 静态渲染回归断言，覆盖收听记录进入头部、标题独占行宽、概要仍完整显示且位于正文之前、简介和文字稿层级，以及既有只读和状态不变检查。回归未在本地执行，程序测试及 Web、Mac 构建留给 GitHub Actions；本轮不触发或追踪 CI。

共享变量汇总与播客产品画板通过生成脚本更新；保留工作区其他任务的备份设置改动。未部署，浏览器布局、手机真机和 Mac 窗口体验仍待验收。
