# 账号密码登录与授权恢复

## 纠正的重复问题

用户反复报告邮件登录先显示失败、刷新后才恢复。现场还观察到：邮件在新标签页打开后，网站会话建立，但插件调用仍失败；随后在原标签页重新连接，MCP 只读调用成功。不能把刷新后的结果当成首次登录成功，也不能把网站登录等同于宿主授权完成。

旧实现中，邮件回跳直接继续 OAuth，原登录页没有会话变化监听；恢复页没有检查已有会话，一律显示链接失败。这两处各自判断完成状态，导致页面与实际会话不一致。

采用架构层修复：服务端会话是唯一登录依据；邮件页只完成会话，原标签页确认 `/auth/session` 后继续它原来的授权地址。`BroadcastChannel` 只传递 `session-changed` 提示；没有跨标签页通信时，恢复焦点和页面显示事件继续检查。单次继续标记防止重复进入宿主回调。没有改动 PKCE 校验或扩大权限。

这是运行时的跨页面状态问题，类型检查无法确认服务端是否已经建立会话；因此先明确状态归属，再用行为回归约束。规则和对应自动检查已登记在根目录 `AGENTS.md`。
