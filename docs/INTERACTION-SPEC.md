# 交互规范与状态流

## 默认状态

屏幕主视觉：卡片网格或单列信息流。无常驻顶部筛选条、侧栏、导航标签、功能文字。只有必要内容状态（时间、即将开始、阅读进度等）可常驻。最小的玻璃球作为交互入口。

## 全局工具

休眠 → hover / focus（PC）或 tap（触屏） → 紧凑图标群展开 → 操作 → 收起。按钮包括：AI、刷新、筛选、搜索、返回顶部。无永久文字标签；tooltip 可通过悬停/聚焦显示。不能仅靠 hover 实现必须可发现的功能。

## 卡片 hover / tap

默认实体卡 → hover 上浮和高亮 → 玻璃图标条入场（收藏、标签、备注、稍后读、更多） → 用户操作 → 图标给予轻量状态回馈 → 退回静态卡。拖拽开始后菜单应避让。

## 筛选与标签

点击全局筛选 icon → 浮层弹出 → 用户选择内容类型/未读/收藏/标签 → 网格轻量过渡 → 浮层可关闭。点击卡片上的标签 icon → 卡片局部标签编辑浮层 → 新建/删除标签 → 保存 → 不在默认卡片铺满标签 chip。

## 预览与阅读

卡片点击 → 快速预览（同一个信息空间中覆盖） → 继续阅读 → 沉浸阅读页。Esc / 返回 / 关闭 → 恢复原滚动位置。进度必须独立于 open 状态，记录上次阅读位置；取消和外部跳转不自动判定完成。

## AI 拖拽状态机

IDLE → ARMING（长按或鼠标拖起） → DRAGGING（镜像、轻阴影） → TARGET_VISIBLE（AI 玻璃球/可用目标显现） → TARGET_HOVER（磁吸、高亮） → DROP（引用写入临时对话状态、动画进入玻璃抽屉） → COMPOSING（输入框自动聚焦，未发送）。取消分支从拖拽状态回到 IDLE，无副作用。

多张卡片拖拽到 AI 时将其附加到已有上下文，去重且可单独移除。实际调用 AI 需要用户主动发送。接收目标需具备视觉反馈，但不能强制复杂精确拖拽才能完成操作，仍应有 click 操作可用。

## 重要提醒

事件接近 → 根据权重和去重规则挑选插入点 → 重要卡片自然加入 → 用户阅读 / 延后 / 完成 / 忽略 → 反馈并从当前高优先级流中降权。切勿突然覆盖长文章或强制跳动布局。

## 手机交互

单列内容流，底部安全区留白；小玻璃球采用点击展开；长按卡片产生拖拽意图但不要与正常滚动混淆；预览用 bottom sheet，向上展开全屏；操作图标有不小于 44px 的可点击区域（视觉图标可以仅 16–20px）。

## 建议动效基线

- icon / focus：120–180ms
- 卡片状态：180–240ms
- 网格重排：240–320ms
- 预览转场：约 280–360ms
- 轻微 spring：仅用于收藏与拖拽吸附
- 支持 prefers-reduced-motion / prefers-reduced-transparency，避免持续闪烁与过量虚化。

## 验证清单

空数据、无网络/失败、长标题、极密信息、重要提醒、已读恢复、页面深度滚动、触屏长按滚动冲突、键盘 tab/Esc、筛选组合、多引用取消、浏览器后退、设备横竖屏与减少动态效果。
