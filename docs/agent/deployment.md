# 部署规范

更新：2026-10-29。规定发布的授权、产物、验收和回退要求。具体步骤见[发布操作手册](../implementation/operations/release-runbook.md)。

## 范围

部署按当前任务已确认的目标、环境和影响执行。同一范围沿用已有授权；构建或合并不自动授权上线。云端服务、MCP 页面、插件、Mac 安装包与数据库变更分别明确范围。

沿用已确认的服务与应用身份。新增目标、改变受众或扩大权限时，先说明影响并取得确认。

## 执行位置

发布测试、程序验证、Web 构建和 Mac 安装包构建统一由 GitHub Actions 执行。本地完成必要的轻量检查后提交推送，读取对应提交或 tag 的检查结果，直接使用该次运行的产物部署或安装。不默认运行本地 `release:prepare`、完整测试或安装包构建。

## 产物与配置

- 记录源码提交和产品版本；候选包含未提交修改时，确认其是否属于发布范围。
- 部署通过检查的同一份产物。源码变化后重新准备候选；检查要求按[测试规范](test.md)与发布流程执行。
- 核对目标当前版本，保留回退标识；发现其他发布已改变目标时，先核对差异。
- 保留现有绑定、权限与配置。凭据通过安全配置提供，清单与产物只记录必要的非秘密信息。
- 数据库变更单独确认兼容性、执行结果与回退限制。

## 验收与回退

上传回执未知时，先查询实际部署。平台确认后核对版本，并检查受影响的健康、权限、接口和宿主资源；界面验收按已有授权执行。

报告区分“候选就绪”“已部署”“已验收”，逐端列出结果与未验证项。回退前核对数据兼容性，回退后复查受影响路径；应用、插件与数据库分别确认结果。

每次发布保存范围、源码与产物、检查结果、部署标识和回退信息。记录只承载当次事实与独有证据，文档历史由 Git 管理。
