# 错误记录规范

更新：2026-10-29。用于保存调试中有复查价值的问题、定位依据和解决情况。本文维护记录方法，具体故障从[错误索引](../records/errors.md)查找。

## 何时记录

需要定位原因、反复出现、影响交付或尚未解决的问题都要记录。一次修正即可消除、没有复查价值的输入笔误不单独建档。记录在定位过程中更新，未解决的问题也保留已知事实和下一步。

## 查找与归档

1. 开始排查时，先在错误索引按报错原文、症状、模块和平台查找；再核对旧记录的版本、环境和触发条件是否适用。
2. 复用同一事件已有的诊断正文；没有正文时，在 `docs/records/YYYY-MM-DD-topic/diagnosis.md` 记录。一个事件有多个独立问题时，用 `diagnosis-<symptom>.md` 区分。
3. 已有 README、测试报告或故障报告完整描述问题时，直接索引该文件，不另抄一份。附件留在原事件目录，临时完整日志放仓库外临时目录。
4. 在事件 README 中加入诊断入口，并在错误索引登记日期、平台或模块、症状关键词和正文路径；原因、状态和解决细节只在诊断正文维护。

## 诊断正文

按以下字段写实际内容；尚不明确的项写“未确认”并注明下一步，不把猜测写成原因。

| 字段 | 内容 |
| --- | --- |
| 问题与状态 | 清楚的症状标题；待定位、已定位、已修复待验证或已验证；最近检查日期 |
| 环境与触发 | 平台、运行入口、相关版本或工作区状态、最小触发步骤、预期与实际结果 |
| 定位依据 | 必要的报错原文、相关代码与证据链接；区分观察、推测和已证实原因 |
| 处理情况 | 已执行的修改或操作、结果、仍有价值的失败尝试；候选办法注明未执行 |
| 验证与后续 | 实际检查方式和结果、适用范围、剩余问题及下一步；修复位置或提交已知时附链接 |

保留能帮助下次排除错误方向的尝试，不逐条复制终端输出或聊天过程。日志与截图按[文件管理规范](file-management.md)处理，只保留必要且不含秘密、个人内容的证据。

## 解决与复发

- 状态随证据更新：原因明确才写“已定位”，改动完成但未验证写“已修复待验证”，直接相关检查通过才写“已验证”。不能复现不等于已解决。
- 同一轮排查原位更新；结案后在新版本复发，新增事件并关联旧记录，保留原验证范围。相同报错不自动认定为相同原因。
- 待办与排期按[事项管理](issue-tracker.md)处理，诊断文件保存事实和证据。确需改变长期规则时更新对应规范；故障经过保留在记录中。

检查索引能否按症状找到正文、证据链接是否可用，以及正文是否写清已知原因、处理结果和未确认部分。
