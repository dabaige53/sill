# 测试规范

更新：2026-10-29。选择检查和报告验证结果时使用。具体命令与工具见[测试目录](../../tests/README.md)和[测试操作说明](../implementation/testing.md)。

## 授权与范围

- 按本次改动及直接影响范围选择检查。相关检查通过后停止；出现新改动、失败或具体跨模块风险时再扩大范围。
- 浏览器、视觉自动化、e2e 和 Mac 窗口自动化须有当前任务明确授权；完整 e2e 另行确认。开发请求、skill 默认流程和 CI 配置不自动授予本地界面测试权限。
- 未获界面测试授权时，完成适用的非界面检查并标明未验证，不例行追加测试许可问题。
- 发布测试和程序验证由 GitHub Actions 执行，包括 Web 核心测试、服务端测试和 Swift 后台测试。本地默认只做文件、差异等轻量检查后提交推送；仅在用户明确要求本地排查时运行必要的针对性检查。
- Web 构建和 Mac 安装包构建也在 GitHub Actions 执行。读取对应提交的运行结果与产物，不在本地重复构建。
- 使用独立合成数据；按[本地测试](../implementation/operations/local-testing.md)隔离真实账号和用户内容。

## 有效验证

- 检查用户实际操作及受影响的失败路径；缺陷回归应在撤掉修复时失败。
- 根据风险选择静态检查、类型检查、构建和针对性测试。合成测试、构建与真实设备体验各自提供不同证据。
- 用户要求精简测试时，优先移除退役入口和重复覆盖；保留仍适用的行为检查。明确授权的缺陷修复可补必要回归。

## 完成标准

报告检查对象、执行结果与未验证范围。区分本轮检查、远端 CI 和历史证据；性能数据只说明测得的指标，不能代替流畅度或界面验收。源码、构建、部署和体验确认分别记录。
