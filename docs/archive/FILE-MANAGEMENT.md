# 文件管理规范

已被 [文件管理规范](../guides/file-management.md) 替代。

状态：现行文件管理规则。更新：2026-10-16。适用于仓库内容与本地工作文件，不改变产品范围、业务实现或发布状态。新规范已确认，见 [文件管理规范（新）](../guides/file-management.md) 与 [代码规范](../guides/code-standards.md)；仓库迁移完成后，本文移入归档。

## 入口与职责

从项目 [README](../../README.md) 进入；找文档用 [文档目录](../README.md)，找构建命令用 [脚本目录](../../scripts/README.md)，找测试与报告用 [测试目录](../../tests/README.md)。新增目录或更改路径时，同步这些入口及 `scripts/check-files.mjs`。

| 路径 | 放什么 | 管理方式 |
| --- | --- | --- |
| `README.md` | 项目说明、启动、当前状态入口 | 简短导航；详细规则在对应专题维护 |
| `pr.md` | 当前待提交的 PR 正文 | 按已完成变更维护；只写真实证据；不作为历史发布记录 |
| `.github/pull_request_template.md` | 可复用的 PR 正文模板 | 固定 Summary、Evidence、Merge Danger 三节；创建 PR 时填写具体内容 |
| `GLOSSARY.md` | 已确认业务术语；按需建立 | 全项目共用；未定义术语先澄清，不创建空表 |
| `docs/agents/` | 工程技能的事项管理、标签映射、领域读取规则 | 使用技能约定的小写文件名；修改后更新导航并检查 |
| `docs/adr/` | 按需新增的架构决策记录 | 四位编号与主题名；保留并引用 `docs/design/decisions.md`，不搬动旧记录 |
| `AGENTS.md` | Agent 的项目约束 | 保留授权与产品边界，不写操作日志 |
| `package.json`、`package-lock.json` | 命令、依赖及锁定版本 | 同步维护；不手改锁文件 |
| `.gitignore`、`.env.example` | 忽略规则、环境变量示例 | 示例只含通用变量名和非秘密示例 |
| `plugin.json`、`.app.json` | 插件描述与 App 绑定 | 与发布配置一起检查；修改不代表已发布 |
| `sill.config.example.json`、`requirements-sandbox.txt` | 历史运行配置示例、沙箱依赖 | 保留兼容用途，不当作默认启动要求 |
| `src/` | 共享 Web 源码 | 按数据、服务、视图、交互、样式组织 |
| `server/` | 本地服务、共用规则、存储与历史服务 | 当前本地入口 `local.mjs`；旧入口保留隔离 |
| `server/cloud/` | 云端 HTTP、MCP、授权和页面适配 | 与本地路径分别验证，不互相代替验收 |
| `web/` | 浏览器端宿主、云端及历史功能适配 | 入口由构建脚本决定，不在这里复制共享卡片实现 |
| `native/macos/` | Swift 原生源码、启动和检查 | 运行数据位置见原生 README |
| `assets/` | 产品品牌资源 | 用于产品与发布的品牌图标 |
| `design-system/` | 设计规范、tokens、组件、画板及设计资源 | 设计规则在该目录维护；产品采用情况单独验证 |
| `docs/` | 产品、架构、操作、交付与历史说明 | 由 `docs/README.md` 分类索引 |
| `docs/examples/` | 合成示例、待实现接口及调用样例 | 标明设计状态；不放真实用户内容与凭据 |
| `docs/validation/` | 需要长期保留的人工验收证据 | 每次验收独立目录，说明日期、环境、范围、结果 |
| `scripts/` | 构建、命令行、检查和 WASM 样例 | 输入输出见 `scripts/README.md` |
| `tests/`、`tests/helpers/` | 自动检查、共享测试工具、历史报告 | 可重复检查与历史结果分别说明 |
| `deploy/cloud/` | 部署配置与客户端公开配置 | 不放凭据；修改本地文件不等于修改线上 |
| `deploy/sill/` | 插件发布身份及候选配置 | 当前构建读取 `release.json`；其他文件保留历史语境 |
| `deploy/releases/` | 已保留的发布快照与清单 | 只作该次发布的证据和回退材料，不手改旧快照 |
| `supabase/drafts/`、`supabase/migrations/` | SQL 准备材料及版本迁移 | 草案不等于已应用；本次不调整 SQL 或生产数据 |
| `skills/` | 随项目交付的 Agent 技能 | 插件构建复制源文件，不在产物里编辑 |
| `.github/` | CI 工作流 | 检查自动化不证明真实环境已验收 |
| `.claude/`、`.agents/` | 宿主开发配置及项目 Agent 资源 | 不放个人秘密；空目录不强制提交 |
| `index.html` | 已纳入 Git 的本地构建页面 | 特例：由 `src/` 生成；修改源文件后重建，不直接编辑 |
| `dist/` | 云端页面、Worker、插件、Mac 包等构建产物 | 不纳入 Git；可重建；清理前确认没有仅存于此的交付物 |
| `tests/artifacts/` | 自动测试截图、录像、日志与临时结果 | 不纳入 Git；要留作交付证据时审阅后复制到 `docs/validation/` |
| `node_modules/`、`__pycache__/`、`.sandbox-venv/`、`.wrangler/`、`supabase/.temp/` | 依赖与工具缓存 | 不纳入 Git；不是项目源码 |
| `.sill/`、`.env`、`.env.*`、`sill.config.json`、`*.sqlite*` | 本地卡片、运行状态、私有配置或数据库 | `.env.example` 除外，其余不纳入 Git，不自动清理 |

不为了目录对称建立空目录。根目录只保留上表已有入口、配置和目录；新文件先判断能否放入已有位置。

## 新增与命名

- JavaScript 沿用 `kebab-case.js` / `.mjs`，Node 测试用 `*.test.mjs`；保留既有 `.cjs`、Python 与 Swift 命名，不批量改名。
- 工程技能配置保留 `docs/agents/issue-tracker.md`、`triage-labels.md`、`domain.md`。架构决策使用 `docs/adr/NNNN-topic.md`。这两类文件遵循技能约定；术语表与决策仅在内容确认后建立。
- 新增长期说明用 `UPPER-KEBAB-CASE.md`，目录说明用 `README.md`。稳定专题只维护一份；避免 `final`、`latest`、`新建`、`副本` 等名字。
- 发布或阶段记录用 `TOPIC-YYYYMMDD.md`。同日多次事件在同一记录中注明时间与版本。
- 验收目录用 `docs/validation/<topic>-YYYYMMDD/`，同日确需分批时增加有意义的后缀。证据与说明放在一起。
- 临时操作输入、导出和调试文件放系统临时目录或被忽略的专用运行目录；不要往根目录堆放截图、ZIP、日志与卡片导出。
- 新增入口文件时更新相邻 README；新增顶层目录时同时更新本规范与文件检查允许列表。

## 文档状态与依据

文档首页写明用途、适用运行路径、状态和更新日期。状态可用：现行规则、设计草案、操作说明、阶段记录、历史参考。记录中的测试结论只适用于注明的环境、版本和日期。

| 问题 | 维护位置 |
| --- | --- |
| V1 产品方向与授权边界 | `AGENTS.md`、`docs/product/agent-mcp.md`、`docs/guides/handoff.md`；交接约定不表示已实现 |
| 本地卡片操作 | `docs/guides/local-operations.md` 与当前本地代码 |
| 插件日常使用与排查 | `docs/guides/plugin-runbook.md`；后续变更同时查日期记录与发布配置 |
| 某次发布或验收发生了什么 | 对应日期的发布记录、快照清单和验证证据 |
| 当前运行行为 | 对应源码、构建配置及本次实际检查；无法检查时标为待确认 |
| 设计约束 | `design-system/README.md`、`docs/design/system.md`、交互规范与设计决策 |

已发现历史差异：`AGENT-MCP.md`、`DEVELOPMENT.md` 与后续本地操作、云端发布记录对实现状态的描述不同。按运行路径和记录日期逐项核对；不得仅凭新日期或文件移动宣布旧限制已解决。本次整理不关闭两个 P1，也不补做线上验收。

旧文档保留原路径，通过目录分类标注历史用途。后续真正归档需先检查入链和脚本引用、更新引用并验证，再移动；没有替代依据时不删除。

## 工程事项与领域文档

GitHub Issues 使用 `dabaige53/sill`。技能配置集中在 `docs/agents/`，从 `AGENTS.md` 和文档目录进入。项目采用 single-context：根目录 `GLOSSARY.md` 与 `docs/adr/` 按需建立。已有设计决策保留原路径；新决策需说明与旧决策的关系。当前配置不创建空目录或空术语表。

PR 正文使用 [PR 模板](../../.github/pull_request_template.md)，当前正文保存为根目录 [pr.md](../../pr.md)。这两个文件遵循 PR 技能的固定结构，不增加状态前言。模板中的说明在提交时替换为具体内容；本次正文不得含占位文字。后续创建 PR 可通过 `--body-file pr.md` 读取正文；保存文件不等于创建或发布 PR。

## 源文件与产物

1. 修改源文件和对应示例，不在 `dist/`、发布快照或 `index.html` 中修补实现。
2. 运行对应构建，检查输出路径；本地页面更新后提交源文件及生成的 `index.html`。
3. 新发布快照需记录版本、构建来源、检查结果和回退说明；既有日期目录保持原样。是否发布按该次授权执行。
4. 测试自动输出留在 `tests/artifacts/`；选择长期证据时去除个人内容、token、授权码、浏览器存储等敏感数据，保留检查方法与结论。
5. 设计系统组件和产品运行代码各有职责。修改规范时检查实际采用位置，不另建一份相同的品牌或组件资源。

## 数据、备份与清理

项目本地卡片在 `.sill/local/cards.json`；Mac 原生版数据及草稿在 `~/Library/Application Support/Sill/`。它们是两份独立数据，不自动互传。浏览器草稿和状态也不是源码。Git 与发布包不能代替用户内容备份。

需要备份本地 JSON 时先停止写入服务，复制到仓库外的专用备份位置，记录时间与来源。先在隔离临时目录验证能读取，再在明确授权下恢复；保留恢复前副本。历史备份协议见 `CONTENT-BACKUPS.md`，不据此声称当前所有路径都有自动备份。

每次交付前运行文件检查并查看 `git status --short`。每次发布后整理当次记录和证据。空间不足时先检查 `dist/`、`tests/artifacts/` 和依赖缓存；这些文件可重建，但不提供自动删除命令。用户数据、未提交内容、历史证据、SQL 迁移及发布快照均不按年龄自动删除。

## 自动检查与完成标准

```sh
npm run files:check
```

检查根目录归属、文档目录及历史测试报告是否有导航、管理入口的本地链接、已被 Git 跟踪的本地数据与缓存。检查只读取文件名、导航正文和 Git 索引，不读取私有配置或卡片内容，不联网、不写入、不清理。

该命令已接入 `npm test`。它不递归检查所有历史文档链接、不检查链接锚点或外部网址，也不是秘密扫描器、业务测试或备份验证。新增根目录被拒绝时，先确定职责，再同步规则。

完成标准：文件有归属、文档有入口、来源与产物可区分、数据与秘密有隔离规则、保留和归档有条件、检查可重复执行。业务模块拆分和线上变更不属于本次文件整理。
