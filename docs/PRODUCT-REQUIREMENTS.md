# Quiet Glass — 产品需求文档

状态：V0.1 产品体验基线，2026-10-11；源于产品共创对话。此文件是讨论后的整理版，不是对每项需求的最终验收承诺。

## 1. 产品定义

一个以卡片为唯一主要内容单元的**个人动态信息空间**，统一聚合资讯、邮件、笔记、任务、日程、提醒、阅读历史、推荐与 AI 洞察。用户主要动作是自然下滑和阅读；系统在合适时间、合适位置，让真正需要关注的信息以卡片出现。

价值主张：以最低理解成本、最低打扰和恰当的交互反馈，帮助用户快速发现下一步应该关注或处理的事。

**不是**传统 Dashboard、资讯门户、待办清单、常驻标签管理页、瀑布流图库或后台 SaaS。

## 2. 视觉总原则

1. 默认页面只有卡片。无侧边栏、顶部筛选器、欢迎 Banner、常驻导航和工具文案。
2. 参考 OpenAI Codex 的简洁、Apple / macOS / iOS 的克制与 Liquid Glass 的精细材质，而不是复制某产品完整布局。
3. 玻璃用于控制层（悬浮 AI 球、临时工具、筛选、预览层），内容卡片不应通篇玻璃化。
4. 轻暖白底色、实体浅色卡片、柔和描边与阴影、黑白灰为主，颜色只传达状态；留白服务可读性，不制造空洞。
5. 卡片可以有多种表达，但统一字体、留白、图标笔画、材质、状态语义；尽量不用图标旁的解释性文字。
6. 卡片内容本身优先于装饰；标签和收藏等操作痕迹默认隐藏。
7. PC 与手机一致的行为模型，适配不同触发方式。

## 3. 卡片系统

候选业务类型：资讯 Article、邮件 Mail、笔记 Note、待办 Task、日程 Event、时间敏感提醒 Reminder、媒体 Media、阅读统计 Insight、AI 关联 Discovery、个人回顾 Recap、下一步行动建议 Action，以及通用链接/收藏。

注意：**收藏、稍后读、已打开、已读、标签**首先是跨卡片状态，不能因为入口不同就重复制造业务卡片种类。

外观基础型：A 文本标准卡、B 图文卡、C 提醒/状态微卡、D 数据与进度卡。可根据内容密度混用高度和跨列，但避免各自变成不一致的 UI 系统。

所有卡片至少具有：稳定 ID、内容类型、标题/摘要、时间、可选来源、优先级、阅读/完成状态、标签集合、行为可用性。不同类型再有业务字段。

## 4. 信息流编排

- 系统按重要程度、时间窗口、兴趣、尚未处理状态和上下文，动态决定卡片出现的位置。
- 重要日程会前自然插入提醒卡片；任务到临近截止的时间点重新出现；刷新可揭示新内容。
- 不应把重要提醒隐藏在机械倒序时间轴深处。
- 不得频繁重复同一提醒；需要去重、冷却时间、可延后/忽略机制。
- 刷新不强制把用户拉到顶部；新卡片可暂存，用户确认后加入。
- 阅读时长、阅读文章数、笔记回顾可以由反馈型微卡承担，但避免主动出现得过于频繁。
- 系统排序应可解释，至少区分紧急优先、未读优先、时间排序等可筛选视图。

## 5. 操作层

默认几乎不可见：
- 页面边缘/右下角保留一个低存在感的玻璃 AI 入口。
- 悬停或点击展开纯图标的刷新、筛选、搜索、返回顶部等操作；鼠标悬停图标才可显示轻提示。
- PC 卡片 hover 时浮现收藏、备注、标签、更多等小图标。
- 手机通过轻触、长按及可发现的菜单入口替代 hover。
- 筛选用按需唤出的玻璃浮层；标签筛选结束后收起。
- 卡片内标签编辑、标记、备注仅在对应操作态出现。

## 6. 核心拖拽

拖动卡片时才出现可以接收卡片的目标区。拖到 AI 玻璃球 → 球体磁吸/扩大 → 释放后展开聊天浮层，并将该卡片添加为可移除引用。支持多选卡片作为 AI 上下文。**释放仅打开对话并聚焦输入，不会自动提交问题**。

其他可选接收动作：收藏、稍后阅读、标签归类。不能在默认页面摆出许多放置区。取消拖拽应回到原位，不能错误写入已读状态。

## 7. 阅读与跳转

单击卡片通常先进入轻量预览（桌面浮层、手机底部抽屉至全屏）。长文和笔记允许继续进入完整阅读；需要跳出网站时，通过明确的「打开原文」动作。关闭或后退恢复信息流原滚动位置。

打开过 ≠ 阅读完。已打开卡片可适度灰化，但保证仍可读。阅读进度采用小巧圆环或条形进度，可恢复阅读位置。对原文、附件及跨服务连接要明确标注来源。

## 8. 微交互与可访问性

候选动效：卡片悬浮 2px、玻璃工具淡入、书签回弹、完成任务收拢、圆环进度、提醒 icon 短时呼吸、刷新旋转、新卡片自然插入、卡片共享元素过渡、拖拽磁吸、多选引用、轻量撤销。

交互必须有逻辑意义而非到处永久循环动画；提供键盘可达性、减少动态效果、减少透明度、足够对比度、合理触控范围和用户可取消的动作。

## 9. 第一阶段范围与边界

V0 先完成原子组件、卡片模板、设计变量、响应式、悬浮控件、卡片预览/阅读、标签/筛选、拖拽 AI、交互实验室与可操作的模拟数据。V1 再考虑真实邮件、日历、阅读源、笔记同步、认证、权限、AI API 和排序策略。

尚待确定：信息流排序公式、重要事件推送阈值、数据源优先级、跨设备同步、隐私和权限、AI 成本限制、离线能力与正式部署方式。
