# 动效开发与排查

更新：2026-10-27。

修改、排查或审查动画、滚动、抽屉和手势时使用本文。经验来自[10 月 25—27 日 Codex 动效复盘](../records/2026-10-27-codex-motion-retro/README.md)。本文规定开发方法；产品当前效果与逐端确认看[动画清单](../product/animation-checklist.md)，数值看[设计变量](../../design-system/tokens/foundation.json)，视觉规则看[动效手册](../../design-system/handbook/motion.md)。

## 1. 先固定操作与当前决定

开始前写清：平台、输入方式、入口、连续操作、实际现象、预期结果。用户说“下滑”“上推”“收缩”“卡”，先对应到具体界面和手势；触控板双指、鼠标滚轮、按住拖动和手机手指分别判断。

从动画清单最新反馈找到本项的决定。保留原有认可范围；后续新增问题单独记。参考替换、暂缓、恢复原方案和取消能力，都要反映在当前执行入口，历史经过留在记录中。

本步完成条件：能按用户的原操作触发问题，或明确标为“未复现，按源码排查”；能指出本次采用的决定及保留的效果。

## 2. 参考到交互链路

用户要求参考某个实现时，逐项核对以下内容，再写适配方案：

| 核对内容 | 要回答的问题 |
| --- | --- |
| 真实元素 | 哪个产品按钮、卡片或内容层在动？事件是否实际绑定？ |
| 输入与触发 | 是滚动还是拖动？达标只表示就绪，还是立即执行？何时释放或取消？ |
| 运动对象 | 移动内部内容、整个滚动窗口，还是抽屉？背景、遮罩和工具由谁带动？ |
| 生命周期 | 谁挂载和卸载？怎样开关、嵌套、恢复滚动、返回焦点？ |
| 运动计算 | 位移阻力、释放速度、回位、停止条件分别是什么？ |
| 适配差异 | 采用、保留、停用哪些能力？每个差异的产品理由是什么？ |

只抄时长和弹簧不能说明完成还原。静态 HTML 中的 transform 是某一帧的结果；还需要原实现的状态、事件、样式和退出处理。参考中的模拟请求等待与示例布局，只有在本次产品决定需要时才采用。

引入成熟组件时，先保留其原有的手势、嵌套、模态、滚动锁定和键盘处理，再列出必须替换的部分。每停用一项能力，都确认由谁接管。接入 Vaul 的最新决定见动画清单与对应 ADR；复盘中的试验不自动成为现行配置。

本步完成条件：每个参考行为都有产品对应元素和明确差异；尚未接入的能力如实标明。

## 3. 先查控制冲突，再调速度

同一元素的同一属性，在同一阶段只有一个控制者。不同属性可以分开控制；外框、遮罩、背景和工具需要按同一交接阶段运动。

- 普通正文滚动交给浏览器。应用只在产品手势需要时接管，并在回位或退出完成后归还。
- 手机触摸、鼠标按住拖动、wheel 分别处理。wheel 可能来自滚轮或触控板；静默时间只能估计输入结束。不能把它当作真实 pointerup，也不能仅凭 delta 大小确定设备。
- 新操作接手时，先取得当前可见位置、透明度或裁切进度，再取消旧动画。回位没结束时，状态不能提前记为归零。
- 组件替换或关闭使旧完成回调失效。取消也要清理临时样式、操作锁与监听，恢复可操作状态。
- 容器和内部按钮分别分配缩放职责；成熟组件与项目代码不能同时写同一层的背景变换。

本步完成条件：能列出开始、跟手、释放、回位、关闭各阶段的控制者；没有两套代码同时移动同一内容。

## 4. 按现象定位

| 实际现象 | 优先检查 | 再决定的动作 |
| --- | --- | --- |
| 用力下拉距离大、空白多 | 可见位移上限、阻力曲线、惯性是否仍在累计 | 收紧位移范围；单独核对刷新门槛 |
| 等一会儿才开始回位或关闭 | 输入结束判断、反复续期的计时、反馈等待 | 保留必要判定，去掉动作前多余等待 |
| 运动中途停顿 | 节点重建、尺寸读写交错、布局或绘制工作 | 按证据修复；未测量时不声称掉帧根因 |
| 回到零时突然停住 | 是否强制清零速度、提前结束、叠加 CSS 过渡 | 接续当前状态，核对停止条件 |
| 前层动了，背景晚一步 | 前后层控制者、进度和取消路径 | 统一交接；检查成熟组件的恢复逻辑是否覆盖项目状态 |
| 勾选时闪白、阅读位置跳动 | 是否重建详情、整网格重画、内容相同却被判为变化 | 局部更新圆圈、文字、计数和颜色 |
| 全屏切换白屏或两段变化 | 旧内容何时消失，新布局何时出现 | 保留可见内容完成交接，再按当前设计切换布局 |
| 改了源码，用户仍看到旧效果 | 服务进程目录、当前端口、源码或产物、缓存、数据后端 | 先确认用户页面确实来自本次工作目录 |

只在确认问题层级后调参。位移上限控制“拉多远”，刚度和阻尼控制“怎样回位”，释放速度控制衔接，停止阈值控制收尾；它们不能互相代替。按角色使用设计变量，不把一组弹簧复制到全部动效。

## 5. 保留阅读状态，分开执行与反馈

任务勾选、收藏和提醒等状态变化，只更新实际变化部分。保留正文、工具、播放器和输入节点，以及焦点、滚动位置和草稿。内容没变时先检查变化判断，不用延时或额外淡入掩盖重画。

详情打开期间，背景筛选成员变化按产品当前决定处理。关闭前保留返回目标；目标确实失效时采用规定的退出方式。嵌套详情返回保留父层节点与阅读位置。

首次加载、后续新增、产品内刷新和浏览器整页刷新分别处理。首次获得数据不能自动算“新卡片到达”；刷新圆环也不能因初始禁用样式而自行显示。

请求提交、结果写回、内容回位与反馈展示分别计时。最短加载反馈可以保证用户看见状态，但不延后真实请求和数据合入；请求没结束时也不能仅凭展示计时宣告成功。新操作能取消旧反馈。

## 6. 检查实际失败路径

检查选择与授权以[测试与验证](test.md)为准。命令从 package.json、测试目录和现有 CI 读取，避免另存一套命令清单。

- 只验证本次改变和直接影响的路径。改过 apps/web 的任务，交付或提交前按项目规则运行一次 test:core；必要检查通过后，除非有新改动或失败，不重复跑全集。用户明确要求只修改、不测试时沿用该范围并如实记录。
- 测试操作与用户验收步骤一致。例如“输入查询 → 失焦 → 再次聚焦”，不能先清空查询再检查。
- 与计时、取消有关的合成测试，推进计时器和绘制帧；临时撤掉修复时应能失败。按已发生的问题补检查，不为假设场景建立通用框架。
- 节点身份、重复请求、旧回调、取消清理和焦点保留，可以用非浏览器测试检查。真实触摸、系统键盘、惯性、视觉交接和流畅度，分别需要对应环境的证据。
- 向用户交验前，确认工作目录、页面来源、前端与数据服务、必要的示例内容。端口能返回 HTML 只证明页面服务可达。

窄窗口、桌面 WebKit、手机浏览器、安装版 PWA、iOS 原生和 Mac 原生分别记录。共享源码、测试通过、构建完成和 PR 合并，不代替另一平台的实际验收。

## 7. 交付与审查

使用动画清单已有的[逐项验收说明](../product/animation-checklist.md#逐项验收说明)：编号和名称 → 平台 → 位置 → 动画 → 当前参数 → 预期效果。只列本轮已实现、用户能触发的项目，保留已确认、待复核、待定和不适用状态。

审查者重点判断：参考是否完整适配、手势归属是否清楚、连续反向是否自然、内容状态是否保留，以及证据是否覆盖结论。实现者提供对应文件、原操作和检查结果，审查不从零重复全部探索。

固定语法、文件位置、失效引用和生成数据过期等机械问题，交给现有检查。只有出现具体漏检时才补最小检查；视觉与跨文件交接判断留在审查中。

改动同时维护当前规则、设计变量和逐端状态；历史证据留在 records。交接文档标出被替代方案，参数指向当前来源。动画工作台的历史经验不构成恢复已删除工作台的决定。
