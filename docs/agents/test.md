# 测试与验证

更新：2026-10-27。本文集中维护 Sill 的测试授权与验证边界；测试位置和命令见 [测试目录](../../tests/README.md)。

## 授权与范围

完整本地流程见 [Web 与 Mac 本地测试](../guides/local-testing.md)：两端各用独立测试目录，与生产账号隔离。


- 用户未明确要求时，不执行浏览器测试、浏览器视觉自动化或 e2e 测试。修改界面、修复问题、打开页面给用户查看，都不自动构成测试授权。
- 只有用户明确确认需要时，才执行浏览器测试或完整 e2e 测试；不得因设计手册、skill、交接文件或默认验收流程要求而自行启动。
- 获准执行 e2e 时，只验证本次修改涉及的功能与直接受影响的场景；完整 e2e 套件须另有用户明确授权。不因局部失败扩大为全量回归。
- 未获授权时直接跳过，不把询问是否执行浏览器或 e2e 测试作为例行步骤。
- 默认只运行本次改动和直接影响范围的检查；相关检查通过后停止。只有用户明确要求，或出现具体跨模块风险、失败时，才说明原因并扩大范围。
- 改过 `apps/web/` 的任务，交付或提交前运行一次 `npm run test:core`。共享假对象和样式名可能在其他 Web 测试文件中失败，只跑局部测试会漏掉。用户明确要求只修改、不测试时，按该范围执行并标明未检查。
- 非界面检查按变更风险选择静态检查、类型检查、构建和针对性测试。未执行的浏览器或 e2e 检查如实说明，不写为通过。

- Apple 窗口自动化、自动点击和视觉检查同样需要当前任务的明确授权。后台 Swift 测试不属于界面自动化。
- 通用代码规则要求实际渲染或界面验收时，仍按本文确定执行范围；未获授权的部分标为未验证，不以构建或后台测试通过替代。

## 测试精简

- 用户要求减少测试时，优先删除退役入口和过渡断言、合并重复覆盖、移除固定等待；说明删减依据与保留的行为覆盖，不借精简任务新增测试范围。
- 明确要求“直接删除、无需再测”时沿用该任务范围，记录未重新运行检查。已有通过结果只属于其当时版本，不自动覆盖后续删除。
- 单独获准的缺陷修复仍可增加能复现真实问题的必要回归；不将该修复与测试精简混为同一目标。

## 动效与计时

- 动画、滚动、手势的时长和间隔规则，用 `tests/web/` 的合成测试验证，不在浏览器里逐帧录制。改动对应的测试见 [测试目录](../../tests/README.md)「按改动选择检查」。
- 合成计时器和绘制帧不会自己运行：`f.flush(undefined, ms)` 模拟过了 ms 毫秒，`f.flush(f.frames)` 推进一帧。只发事件、不推进时间的测试，旧实现也会通过；新增这类测试后，临时撤掉修复确认它会失败。
- 既有排查曾遇到 Claude 桌面浏览器面板隐藏后不出帧、滚动事件和动画停住，以及调整面板后模拟手机尺寸重置。不要把隐藏面板的停帧当成产品动效故障；获准使用该面板时先确认可见状态与实际尺寸，计时规则仍用合成测试检查。

## 自动检查

- 已配置的 CI 按工作流触发条件执行；CI 中已有的浏览器流程不构成本地执行授权。
- `macos.yml` 在 PR、main 提交及手动触发时只执行 Apple lint 和 Swift 非界面测试。Mac 应用打包与签名验证仅在推送 tag 时运行；不启动应用窗口或执行 XCUITest。
- 性能基准按需运行，不作为动画流畅或界面验收通过的证据。
- 交付说明区分本地已运行检查、远端 CI 结果和未验证部分；新增工作流在远端实际运行前只算配置完成。
