# Agent 长期参考

更新：2026-10-27。本目录集中维护 agent 的长期开发、设计、测试、审查和交付规则；按任务选择阅读。产品规则、设计手册、使用说明、专题方案和历史记录保留各自目录，完整导航见[文档目录](../README.md)。

## 核对最新决定与代码

1. 先读当前用户要求；任务承接旧聊天时，再读相关线程的最新消息，找出后续确认、撤回、替代和暂缓的决定。线程标题、缓存摘要和一次通过记录不能代表最终决定。
2. 检查当前分支、提交和工作区改动，再读取相关实现、`package.json`、检查脚本及 CI。命令、模块和参数引用这些来源，避免在长期文档中维护另一套固定值。
3. 分开写目标与现状。用户已确认但代码未接入，写「待实现」；代码已接入但未做对应验证，写「未验证」。文档与代码冲突时，先定位对应决定及实现，不按文档日期选较新的一篇，也不为修正文档擅自改业务行为。
4. 将仍适用的工作方法维护到本目录；产品决定写入对应产品文档、手册或 ADR；过程和实测结果写入 `docs/records/`。被替代的方案保留历史位置，当前入口指向实际采用的方案。
5. 更新后检查路径、引用、内容与代码对应关系，运行本次必要检查。只有真正重新核对过的事实才能写为当前状态；无法取得最新消息、设备或外部回执时，写清证据范围。

维护完成条件：相关规则有一个明确来源；最新决定、代码实现和验证状态能分别追溯；入口及链接可用。根目录 `AGENTS.md` 保留自动加载的边界与导航，`DESIGN.md`、`pr.md` 只保留兼容入口。

每次维护在对应任务记录中分别填写以下三项，并注明核对时间、分支、提交及相关未提交改动：

| 项目 | 必须记录什么 |
| --- | --- |
| 目标 | 用户最新确认的行为、撤回或暂缓的方案；附相关线程标题、ID 和消息时间 |
| 实现 | 当前代码位置、已接入与待实现部分、端之间的差异；区分提交版本和工作区修改 |
| 验证 | 检查命令或用户体验确认、结果及对应版本；区分本轮运行、其他线程报告、历史结果和未验证部分 |

代码存在不等于验证通过，检查通过不等于已经部署。长期文件维护仍适用的规则；有日期的状态表放在 `docs/records/`，避免多处保存不同的“当前状态”。本轮逐份核对见 [2026-10-27 长期参考核对](../records/2026-10-27-agent-reference-audit/README.md)。

## 排查与恢复

沿用各专题指南。排查方法变化时更新原指南；新增问题入口或调整章节位置时更新本表。

| 遇到的问题 | 查阅位置与下一步 |
| --- | --- |
| 修改源码后页面还是旧版 | [本地页面入口与更新](../guides/local-operations.md#页面入口与更新)：区分构建预览与开发热更新，检查产物是否更新 |
| 保存冲突、草稿未保存或写入结果不明 | [本地数据与 AI 操作](../guides/local-operations.md#数据与-ai-操作)、[插件日常使用](../guides/plugin-runbook.md#日常使用规范)：读取当前内容，按原版本和幂等规则核对 |
| 插件无工具、授权失败或侧栏打不开 | [插件排查顺序](../guides/plugin-runbook.md#排查和验收顺序)：固定实际连接对象，再检查授权、发现与页面加载 |
| Mac 卡顿或性能记录异常 | [Mac 性能追踪](macos-performance.md)：按场景采集记录，区分后台指标与窗口行为 |
| 需要备份或恢复本地数据 | [数据与清理规则](file-management.md#7-数据秘密与清理)、[本地操作](../guides/local-operations.md#数据与-ai-操作)：确认数据位置、停止写入、保留副本，再验证恢复文件 |
