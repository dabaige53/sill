# 领域文档

状态：现行规则。更新：2026-10-16。

采用 single-context，整个项目共用一套业务术语和架构决策。

## 阅读规则

- 探索代码前，读取根目录 `GLOSSARY.md`（若存在）。
- 读取 `docs/adr/` 中与当前任务相关的架构决策记录（ADR）。
- 同时查阅 [已有设计决策](../DESIGN-DECISIONS.md)，保留已有决策及编号。
- 文件不存在时继续工作，不创建空术语表或空决策记录。
- 确认新术语或决策后，再通过 `domain-modeling` 建立对应文件。

## 使用规则

- Issue、代码、测试和文档采用术语表中的称呼。
- 缺少定义时记录待澄清项，不自行把新称呼当作既定术语。
- 建议与已有决策冲突时，明确指出对应决策及调整理由。
- 新架构决策存入 `docs/adr/`，使用四位编号和简短主题名；编号接在原设计决策 ADR-21 之后，从 0022 起递增，分配前检查 `docs/adr/` 已有的最大编号。
- 新记录注明日期、状态和相关旧决策；不覆盖历史原文。

目录职责与命名规则见 [文件管理规范](../FILE-MANAGEMENT.md)。
