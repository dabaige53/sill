# 外部备份与设备提醒

更新：2026-10-29。本文说明备份、恢复、通知的操作和部署依赖。能力定义见 `contracts/backup.ts`，工具范围见[Agent 与 MCP](../agent-mcp.md)。

WebDAV 和 R2 只保存备份，不作为产品工作区数据源，也不参与双向同步。定时备份另行实现，本次不改变现有手动备份与恢复流程。

## 备份账号

登录 Sill 后，在设置的数据区域配置自己的备份位置。保存前会检查连接。Mac 和独立网页直接提交给账号接口。助手中的内嵌页面只操作已经配置的位置，不接收密码或密钥。

- WebDAV／坚果云：先在网盘中建立备份文件夹，再填写该文件夹的完整 HTTPS 地址、用户名和应用密码。地址不能跳转到其他主机。服务端默认允许 `dav.jianguoyun.com`，其他 WebDAV 主机需由部署配置明确允许。
- Cloudflare R2：先建立 Bucket，再填写 Account ID、Bucket 名称、Access Key ID 和 Secret Access Key。凭据需允许该 Bucket 的读取与对象写入。
- 更换密码或访问密钥时，选择已有位置，填写相同位置和新凭据，然后点“更新所选位置的凭据”。修改地址或 Bucket 时创建新位置，已有记录仍属于原位置。

服务端按账号和位置加密保存凭据。界面不会回填秘密；快照、MCP 参数与结果均不包含这些凭据。供应商说明见[坚果云 WebDAV](https://help.jianguoyun.com/?tag=webdav)和 [R2 S3 API](https://developers.cloudflare.com/r2/api/s3/api/)。

## 备份、下载与恢复

选择位置并点击“立即备份”。每次操作捕获一份固定快照，上传后读取并核对内容，确认后记录为完成。若回执丢失，先刷新记录并核对原备份；重试沿用原请求和原文件。

历史显示最近 200 条记录。可下载已登记快照，也可预览恢复后的卡片数量、增加和移除数量。确认恢复会替换当前账号的卡片、个人状态、偏好、阅读秒数与播放位置。预览后数据若已变化，恢复被拒绝，需要重新预览。回执不明时可查询恢复结果或重试原恢复。

快照上限 32 MiB。图片、音频和附件保留 URL，不复制外部文件。目标配置、账号会话、系统通知权限和设备去重记录不在快照中。恢复依赖 Sill 数据库中的备份登记和回执；当前不支持数据库全丢失后的网盘扫描、任意文件导入或自动定时备份。

## 设备提醒

在设置中开启“系统提醒”，系统会请求当前设备的通知权限。完成、忽略、稍后提醒、删除卡片以及退出账号，会更新本设备的通知。

- 网页：页面打开时检查到期提醒，切到后台标签仍会检查；浏览器可能延迟后台计时。关闭页面后不再安排新通知。内嵌宿主不申请通知权限，请使用独立网页。
- Mac：已载入的提醒交给系统按时通知。开启提醒后关闭主窗口会保留应用，以继续安排后续提醒；通知点击重新打开主窗口。主动退出应用后，系统仍保留已经安排的通知，但应用不能补排更多通知或读取新的云端内容。

网页只使用通知所需的 Service Worker，不做 Web Push、离线缓存或本地内容同步。通知权限和启用开关按设备保存；卡片的提醒时间和完成状态由账号共用。

## 部署输入

部署前对照目标环境核对以下迁移，按仓库迁移顺序补齐缺失项：

1. `supabase/migrations/20261023020000_https_images.sql`：HTTPS 封面与照片。
2. `supabase/migrations/20261023114649_sill_external_backups.sql`：备份目标、快照登记、恢复回执和权限受控的 RPC。

Worker 需要 `BACKUP_ENCRYPTION_KEY`（64 位十六进制的 256 位密钥），并可配置 `BACKUP_WEBDAV_HOSTS`（逗号分隔的允许主机）。密钥缺失时不发现备份 MCP 工具。更换该密钥会使旧凭据无法解密，现有用户需重新填写备份凭据。生产配置使用部署平台的秘密入口。

同时发布云端网页、Worker 和 Mac 构建。网页需要 `/reminders-worker.js` 路由及同源 Worker 权限；MCP 页面需要宿主接受官方 YouTube 框架与当前卡片资源域名。新增域名后重新打开内嵌页面；不接受嵌入视频的宿主仍可打开来源链接。
