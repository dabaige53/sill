# 卡片 A 字号、资讯阅读与 Mac 设置弹窗

2026-10-20，已采纳。

## 决定

1. **卡片 A 字号与四列。** 卡片标题 16/22，摘要与卡上要点 14/22，卡片头部辅助信息 12/18（新变量 `card-meta`）。桌面信息流最多四列（`col-limit` 4），列宽规则与密度设置不变。搜索框、AI 输入框等原来借用卡片标题字号的地方改用独立的 `input` 17，避免卡片改字号时连带变化。
2. **资讯阅读 B 均衡。** 只用于资讯卡。预览浮层和全屏阅读页用同一套 `article-*` 变量：标题 22/30，小节 17/24，正文 15/25，来源、日期、图注 12/18；正文最大 600，居中，左右 32（手机 20）。日期只在来源行出现一次，写「今天」「昨天」「10/18」。其他 10 类查看页不使用这套变量，沿用原有实现。
3. **Mac 顶栏。** 品牌图标左缘对齐窗口关闭按钮，位于红绿灯正下方；头像仍对齐卡片区右缘。Web 没有红绿灯，规则不变。
4. **设置弹窗。** Web 桌面与 macOS 都在窗口中央打开设置弹窗（宽 840，头部「设置」与关闭钮，左侧分组）。macOS 不再另开系统设置窗口，⌘, 和头像打开同一个弹窗。手机仍为整页。

## 理由

- 卡片在四列下需要更紧的字号，才能在 340 左右的列宽里放下两行标题和三行摘要。
- 资讯正文需要比卡片更松的行距和稳定的行长，但早期 17/29 的方案在桌面显得过大；B 均衡在卡片与正文之间取中。
- Mac 窗口左上角已有红绿灯，图标落在其右下方显得错位；对齐关闭按钮后两者成为一列。
- 设置是一次性的轻操作，弹窗保留主窗口上下文，并与 Web 桌面一致；单独窗口带来另一套标题栏和焦点。

## 不做

- 不把 `article-*` 变量用于卡片或其他详情页，不改卡片正文数据格式。小节、列表、引用、图注的样式先定为变量，正文出现这些结构时再接入。
- 不新增设置搜索、折叠区、属性侧栏或信息表。
- 不改真实卡片内容，不部署。
