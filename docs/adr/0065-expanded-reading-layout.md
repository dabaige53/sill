# 放大阅读页按内容排版

日期：2026-10-23。状态：已采纳。

## 原因

资讯、播客与视频放大后仍沿用预览的窄栏、顶部留白和底部工具占位，桌面阅读空间不足。用户确认仓库放大页原型，并要求同步 Web、Mac 与手机 Web，暂不部署。

## 决定

- 预览保留底部操作胶囊；资讯与媒体放大页将操作放到左上角，关闭和缩小在右上角。顶部占位使用 space-64，正文底部使用 space-24，取消放大页上下渐隐。
- 视频采用 1.6:1 的播放器与文字区分栏，播客采用等宽分栏；两侧可以独立滚动。窄屏回到上下排列，不压缩播放器和文字。
- 资讯放大正文最大宽度使用 reader-measure（920px），目录使用 reader-outline-width（160px）。目录只取 Markdown 的真实标题，不生成「文章开头」或虚构章节；无标题时不显示目录。
- 目录标题用 body 15px、中等字重和 ink；章节用 control 14px，普通项为 muted，当前位置为 accent 与 600 字重。标题层级按实际深度缩进，支持跳转、滚动跟随与收起。手机预览用可展开的「目录」入口，不增加常驻侧栏。
- 展开和收起共用 expandedSpring：mass 1、stiffness 274、damping 27。正文不缩放，操作按钮不从底部飞到顶部；键盘操作即时完成。卡片与信息流之间的原有 cardSpring 保持不变。
- 不改变媒体播放、已读判断、阅读记录、收藏、标签与稍后读的数据操作。原生 iOS 当前只有数据层，不新增原生阅读界面。

## 影响

设计变量、放大页原型、阅读规则与界面对账表同步。Web 使用 ReaderLayout 与 reader-layout.css；Mac 使用 ReaderPage、MediaDetail 与 MarkdownText。设计在线副本仍按 DESIGN.md 的发布流程处理。
