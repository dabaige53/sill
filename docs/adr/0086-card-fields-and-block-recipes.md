# ADR 0086：卡片字段精简与积木配方表

日期：2026-10-28。状态：已接受，实施中。产品尚未投产，用户确认不保留旧数据兼容。部署和清空云端数据需要用户另行确认。

## 原因

- 卡片约定 4.2.0 有 49 个顶层字段。多个字段表达同一概念，例如附件与文件、发件人与作者、发送时间与发布时间。约三分之一的字段只在详情里显示一行文字；`section` 和顶层 `modifiedAt` 没有界面使用。
- 设计手册已经规定「卡片由积木拼成，类型只是配方」，但代码按卡型手写组件，卡面和详情各写一份。Web 端同一种内容有多种写法：文件行 2 种、提醒圈 3 份、来源行约 7 种、卡面摘要 5 种。
- 详情标题下的兜底信息行把剩余字段逐行显示为文字。新增字段没有对应积木时，就会进入这里。

用户确认：字段只保留有交互、计算、筛选或固定卡面位置的结构；纯阅读内容写入正文；每种内容只用一块积木显示。

## 决定：字段

### 保留的 30 个顶层字段

| 分组 | 字段 |
| --- | --- |
| 基础 | `id` `type` `title` `summary` `body` `url` `time` |
| 来源与归类 | `sources` `authors` `publishedAt` `tags` `related` `priority` |
| 待办与日程 | `tasks` `due` `project` `start` `end` `location` `people` `meeting` |
| 文件与图片 | `files` `images` `form` |
| 媒体 | `media` `duration` `chapters` `transcript` `audioUrl` |
| PR | `pullRequest` |

- `people` 只用于日程。
- `form` 只接受 `quote`。
- `images` 是图片列表：封面取第一张，照片卡显示全部。视频卡和照片卡要求列表非空。

### 合并

| 旧字段 | 并入 |
| --- | --- |
| `attachments`、`attachment` | `files` |
| `sender`、`publisher` | `authors` |
| `sentAt`、`takenAt` | `publishedAt` |
| `caption` | `summary` |
| `image`、`photos` | `images` |

### 删除

- 无界面使用：`section`、顶层 `modifiedAt`。
- 只显示一行文字：`savedAt`、`chapterCount`、`timeZone`、`recipients`。
- 产品取舍：`why`、`coverageStart`、`coverageEnd`、`readingEstimate`、`bodyCoverage`。
- PR 快照删除 `files`、`comments`、`author`，保留其余 12 个子字段。

### 个人状态

- 任务完成只记录在个人状态 `taskDone` 中。删除 `tasks[].done`。用户勾选和助手标记完成都写 `taskDone`。
- 标签只记录在卡片 `tags` 中。删除个人状态的 `tags` 与 `tagsEdited`。用户修改标签就是修改卡片标签，沿用现有的保存基准与冲突检查。

### 预计阅读时长

两端在本地按正文去掉 Markdown 标记后的字数计算，统一显示「约 N 分钟阅读」。中文每分钟 400 字，英文每分钟 200 词；中英文分别计算后相加，向上取整到分钟。不再区分全文与现有内容。此条取代 [ADR 0050](0050-explicit-card-fields.md) 中由写入方提供估算及依据的规定，以及 [ADR 0063](0063-markdown-body.md) 的待定项。

### 不保留兼容

产品尚未投产，新结构直接生效：

- 不在读取时转换旧字段。删除现有的旧数据转换，包括 `source`、`kind`、`points`、数组正文和单项 `attachment`。
- 卡片约定改为拒绝已删除的字段，不再原样保留未知字段。
- 约定版本由 4.2.0 升为 5.0.0。云端新增一次数据库迁移，重写字段允许列表，删除旧数据转换函数。JSON Schema、OpenAPI、MCP 工具说明、Swift 客户端和 `skills/sill/references/fields.md` 一起更新。
- 本地 `.sill/local/cards.json` 先备份，再按新结构重建示例数据。

云端在部署时单独清空数据，不写进数据库迁移：

- 保留：账号、外部助手授权（OAuth 客户端、令牌会话、调用方权限、授权审计）、备份目标配置。
- 清空：卡片、个人状态、偏好、阅读统计、写入回执、备份与恢复记录。外部存储中已有的备份文件不动。

## 决定：积木与配方

- 一块积木对应一个组件，Web 与 Mac 各实现一次。卡面使用紧凑档，详情使用完整档。紧凑档控制条数、字号和是否可点击。
- 配方表声明每种卡型在卡面和详情使用哪些积木、顺序和条数上限。配方表放在 `design-system/`，两端读取同一份。卡型组件只保留复合积木。
- 积木顺序沿用设计手册：贴顶媒体 → 头部 → 主角 → 文字与数据 → 条状媒体 → 列表 → 动作。
- 设计手册中没有实现的积木保留为远期储备，在手册中标明「未实现」。「文件条」与「附件」合并为「文件」。新增「信息行」：图标加文字，显示地点、会议、项目、优先级和到期时间。
- 来源行右侧最多放一个状态小件：进度环、计数、剩余时长、相对时间或提醒时刻。
- 复合积木：PR、视频播放器、播客详情、图集。视频与播客的章节、文字稿维持两套实现。
- 删除详情兜底信息行、随手记笔记的卡面变体，以及待办卡在没有子任务时显示卡面摘要的分支。

### 积木

| 组 | 积木 |
| --- | --- |
| 贴顶媒体 | 封面、拼图 |
| 头部 | 来源行；变体「发件人」带头像 |
| 主角 | 标题、金句、时间段 |
| 文字 | 卡面摘要、正文 |
| 条状媒体 | 节目条、文件 |
| 列表 | 勾选清单、信息行、参与者、引用卡 |
| 动作 | 按钮，到点才出现 |
| 复合 | PR、视频播放器、播客详情、图集 |

标签、个人备注、底部工具条和助手操作属于所有详情共用的外框，不写入配方。

### 配方

| 卡型 | 卡面 | 详情 |
| --- | --- | --- |
| 文章 | 封面（有图时）→ 来源行[进度] → 标题 → 卡面摘要 | 来源行 → 标题 → 封面（有图时）→ 正文（带目录） |
| 笔记 | 来源行[进度] → 标题 → 卡面摘要；`quote` 时为来源行 → 金句 | 来源行 → 标题 → 正文 |
| 邮件 | 发件人 → 标题 → 卡面摘要 → 文件（1 个） | 发件人 → 标题 → 正文 → 文件（全部） |
| 待办 | 来源行（项目 · 到期）[完成数] → 标题 → 勾选清单（3 项，未完成优先） | 来源行 → 标题 → 信息行（到期、优先级）→ 勾选清单 → 正文 |
| 提醒 | 来源行[提醒时刻] → 提醒圈与标题 → 卡面摘要 | 来源行 → 提醒圈与标题 → 正文 → 信息行（项目） |
| 日程 | 来源行（日期）[相对时间] → 时间段与标题、信息行（会议、地点）→ 参与者 → 按钮（加入） | 来源行 → 时间段 → 标题 → 信息行（会议与会议码、地点）→ 参与者 → 正文（议程） |
| 视频 | 封面与节目条 → 来源行[剩余时长] → 标题 | 视频播放器 |
| 播客 | 来源行[剩余时长] → 标题 → 卡面摘要 → 节目条 | 播客详情 |
| 摘要 | 来源行[关联数] → 标题 → 卡面摘要 | 来源行 → 标题 → 正文 → 引用卡 |
| 建议 | 来源行 → 标题 → 卡面摘要 → 引用卡（2 张） | 来源行 → 标题 → 正文 → 引用卡 |
| 照片 | 拼图（3 张）→ 来源行（地点 · 日期）[张数] → 标题 → 卡面摘要 | 图集，说明取卡面摘要 |
| 文件 | 来源行[文件数] → 标题 → 卡面摘要 → 文件（3 个） | 来源行 → 标题 → 正文 → 文件（全部） |
| PR | PR（紧凑）→ 按钮（审阅） | PR（完整） |

方括号内是来源行右侧的状态小件。卡面条数为上限，超出部分显示「还有 N 个」。邮件卡面附件在手机和桌面都只显示 1 个；文件卡保持 3 个。

## 实施顺序

在新分支上完成，分两个提交，最后开 PR：

1. 组件改为积木与配方表，外观不变。
2. 删除与合并字段，同时更新设计手册、界面对账表和卡片约定。

用户选择不做截图对照。验证以测试、类型检查、Web 构建和 Swift 构建为准；界面外观一致与否标为未验证。

## 影响

可见变化：

- 带正文的文章、笔记、邮件、文件、摘要和建议卡大多会显示阅读时长。
- PR 详情不再显示改动文件、评论数和「谁想把哪个分支合并到哪里」。
- 建议卡详情不再有理由区块，改为显示正文。
- 摘要卡头不再显示覆盖日期范围。
- 邮件详情不再显示收件人，日程详情不再显示时区，媒体详情不再显示章节数，待办详情不再显示人员。
- 邮件卡面附件由 2–3 个改为 1 个。
- 日程详情的参与者改为头像加名字。
- 旧的随手记笔记按普通笔记显示。
