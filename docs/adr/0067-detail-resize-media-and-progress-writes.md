# 详情放大遮罩、媒体播放与阅读进度写入

日期：2026-10-24。状态：已采纳。

## 原因

用户要求检查打开和关闭卡片、详情上下滑动、放大阅读页时是否缺少动画或卡顿，尤其是视频和播客。代码检查发现以下问题（检查过程见[记录](../records/2026-10-24-detail-motion-audit/README.md)）：

- 放大时阅读页的遮罩在第一帧就换成不透明的页面底色。外框从预览尺寸长大的弹簧动画被同色遮罩盖住，看起来是直接切到全屏白页。
- 播客与视频每次报告播放位置（音频约每秒 4 次，视频每 500ms 一次），整个详情都会重新渲染。文字稿最多 10,000 行，章节也会整份重绘；资讯摘要的 Markdown 每次都重新解析。
- 视频播放器的框架在详情打开、放大的动画进行中插入，跨源页面的加载和动画同时占用主线程。
- 阅读时几乎每次滚动事件都写入进度，每次写入都保存整个工作区：本地写入整份浏览器存储，云端复制并比较整个工作区快照。
- 详情滚动时，工具条每次都在整个详情里查询过渡中的元素。

## 决定

- 阅读页从预览放大时保留预览的遮罩，外框铺满屏幕后再换成页面底色。取消放大时恢复原遮罩。缩小方向不变。
- 文字稿与章节列表只在当前行、可用状态或内容变化时重绘。Markdown 正文只在内容变化时解析。
- 视频播放器的接口照常提前加载。框架等详情中有限时长的动画结束后再插入，最多等 800ms；循环动画不计在内。等待时显示封面，点播放会在播放器就绪后开始。
- 进度条与圆环随滚动逐帧更新。进度本身最多每 500ms 保存一次，保留最远位置。关闭详情、切到后台或离开页面时补存；读完立即保存。
- 工具条的暂停判断只检查详情的直接子元素和第一个浮动工具条。
- 详情中的媒体封面异步解码。

不新增设计变量，不改变弹簧参数、读完规则、播放位置保存规则或媒体数据。
