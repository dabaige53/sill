# 详情文字统一为一个 Markdown 正文字段

日期：2026-10-22。状态：已接受；本次修改约定、云端迁移文件、Web 与 macOS，均未部署。取代 [ADR 0060](0060-card-rebuild-by-type-and-source-marks.md) 与 [ADR 0061](0061-in-app-media-playback-and-pr-cards.md) 设计稿中「要点」作为独立字段的画法。

## 原因

详情里的文字由三个字段拼成：`summary`（一段文字）、`points`（最多 3 条要点）和 `body`（段落数组）。两端各自决定它们的顺序和样式；写入方想表达小标题、列表、引用或加粗时没有位置，只能拆成更多字段或写成纯文本。用户确认：字段拆得越多，后续加工越乱；资讯、汇总等文字内容应当写在一个字段里，用一个开源 Markdown 渲染器统一显示，便于管控。

## 决定

- `body` 改为一个 Markdown（CommonMark）字符串，是详情里唯一的文字内容，最多 500000 字。
- 删除 `points`。要点写成正文里的列表。
- 保留 `summary`，职责改为卡面摘要：一两句纯文本，只用于信息流卡面和搜索结果，详情不再显示。正文为空时，详情把卡面摘要当作一段正文显示。
- 有操作或固定结构的内容仍是独立字段，不写进正文：待办子任务、文件、会议、附件、相关的人与卡片、建议的理由，以及 ADR 0061 计划的文字稿与章节时间。
- 两端都使用开源 Markdown 渲染器，不自写解析。Web 使用 markdown-it；macOS 使用 Swift 官方的 swift-markdown 0.9.0（cmark-gfm），解析后用 SwiftUI 按既有正文样式绘制。
- 渲染规则两端一致：
  - 原始 HTML 不渲染，按文字显示。
  - 图片语法不加载图片，只显示替代文字；Sill 不因正文去外部取内容（[ADR 0033](0033-ai-writes-composio-only.md) 不变）。
  - 链接只接受 http、https 和 mailto，在新窗口打开；其他协议按文字显示。
- 旧卡片在读取时于内存中转换，不改写存量数据：
  - `body` 数组按空行拼成一个字符串。
  - `points` 转为有序列表，放在正文最前面，与原来的显示顺序一致。
  - 旧段落直接按 Markdown 解析，不做转义。
  - 用户或助手下次保存时写入新结构。
- 云端新增数据库迁移：`body` 改为字符串校验，读取时兼容旧数组，不再接受新的 `points`。约定版本由 3.0.0 升为 4.0.0。迁移文件只在本地测试库验证，不部署。
- macOS 与 Web 使用解析后的纯文本进行搜索及卡面摘要回退；解析不修改保存的正文。详情有正文时不重复显示卡面摘要，无正文时把摘要按纯文本显示。
- macOS 的速记与云端默认正文使用字符串；旧草稿替换正文时不再叠加旧要点。
- 编译和后台测试不代替真实窗口验证；[界面对账表](../product/ui-alignment.md) 的实测状态保持「未验证」。
