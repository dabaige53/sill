# 设计决策记录（ADR）

更新：2026-10-16。

ADR-01 至 ADR-08 是 Sill 阶段的决策，保留原文；已被后续决策取代的会注明。ADR-09 起是 Sill 阶段的决策。

## ADR-01：取消侧栏与顶部信息区

原因：用户明确指出收藏、关注、稍后读等都能成为卡片标签与筛选状态，独立侧栏造成重复和注意力分散。结果：默认只显示卡片，筛选按需唤出。

## ADR-02：先做组件实验室，再拼页面

原因：要支持多种卡片来源和交互，不能把全部功能硬编码进单张页面。实施顺序为 token → atoms → card primitives → templates → overlays / motion → feed。

## ADR-03：Liquid Glass 用作交互材料

原因：此前的白色胶囊按钮、大片筛选区被认为像普通 Web UI，缺少 Apple 风格精细感。结果：玻璃材质出现在悬浮 icon、预览和操作层，实体卡片继续保持内容可读。

## ADR-04：按钮图标优先

> 已被 ADR-12 取代。

原因：刷新、筛选、收藏、AI 入口不需要永久文字。结果：操作态出现纯图标，必要时 tooltip，保留可访问名称和触控尺寸。

## ADR-05：拖拽即提问

> 已被 ADR-15 取代：页面不再内置 AI 对话，拖拽只用于收藏、稍后读和标签。

原因：相对于“打开卡片 → 找问 AI 按钮”，用户更希望直接将某张卡片拖至目标自动形成对话上下文。结果：动态出现目标、磁吸、生成引用、聚焦输入，不自动发送。

## ADR-06：状态与类型分离

原因：“收藏”和“稍后读”不应制造重复卡片模板。结果：内容种类与标签/阅读/收藏等状态分别建模。

## ADR-07：提醒自然融入而不是弹窗

原因：整个界面以低干扰阅读为核心。结果：时间敏感事项作为优先卡片注入信息流，具有频率控制与撤销/延后入口。

## ADR-08：原型不等于正式连接

当前演示使用模拟邮件、日程、阅读数据和 AI 回答。正式接入涉及 OAuth、数据权限、同步调度与安全验证，不能以 UI 演示完成推定后端已上线。

## ADR-09：改名 Sill，以设计画布为准

原因：Sill 的玻璃感压过了内容，用户要的是安静、可读的窗台，而不是一块玻璃。结果：品牌、颜色、卡片积木和全部页面重新定稿在 [Sill · 设计画布](https://claude.ai/artifact/487W43yaF9D3Kno8c3ej6b)，本地副本在 `design-system/boards/`。代码、命令和数据路径暂沿用 `sill`。

## ADR-10：点卡片直接看全文

原因：「点卡片 → 预览 → 再点继续阅读」多了一步，用户点开就是想看内容。结果：预览直接显示全部正文；需要更大的阅读空间时点「全屏」。原来的「继续阅读」按钮去掉。

## ADR-11：从卡片本身展开

原因：凭空弹出的面板很生硬，看不出和哪张卡片有关。结果：桌面上预览从被点的卡片原位放大，关闭时缩回原卡片。手机上改用从底部升起的面板（见 ADR-13），因为屏幕窄，原位放大反而看不清过程。

## ADR-12：文字和图标只用一种

原因：图标旁再写一遍同义文字是重复表达，让工具条变重。结果：每个控件要么只有图标（含义通用：关闭、更多、收藏、刷新），要么只有文字（动作具体：加入会议、授权、恢复、全屏）。纯图标控件保留可访问名称。规则写在设计手册「图标」一节。

## ADR-13：手机预览是底部面板

原因：参照手机交互原型，读者在手机上的习惯是「往下读就铺满，在顶部往下拉就退回」。结果：面板升到距顶 64px；往下读时铺满；在顶部下拉先退回半屏，再拉才关闭；滚动时底部操作条让开。

## ADR-14：手势只给目标，过渡负责移动

原因：早期用脚本逐帧驱动位置，触控板惯性一来就卡顿、闪烁，和原型的顺滑差距明显。结果：手势只设定元素该去的位置，由 CSS 过渡带过去；手指按住时暂停过渡紧跟手指；惯性不算手势，手势完成后的残余惯性吞掉。读完上推、下拉关闭、下拉刷新都按这个方式实现。

## ADR-15：页面不做 AI 对话

> 产品目标已由 ADR-20 更新：规划内置助手，但不要求所有操作经过聊天；本段保留当时实现背景。

原因：内容的采集、整理和生成由用户自己的 AI（Codex、Hermes、Claude）通过本地命令完成，页面再做一套聊天是重复的。结果：页面只负责看和轻操作；拖拽卡片只出现收藏、稍后读、标签三个接收区。

## ADR-16：叠卡是一摞牌

原因：叠卡里只滑动文字，看起来像一张卡在换字，用户感觉不到「这里有好几张」。结果：叠卡由整张卡片叠成，左右拖动的是整张卡片，被拖的卡从相邻卡上方经过；单击才在原位展开。

## ADR-17：封面用矢量图

原因：原来的封面是小尺寸位图，放大后发虚，还带着截图残留。结果：内置封面改为 1600×900 的矢量图，任何尺寸都清晰，颜色跟随卡片色调。

## ADR-18：数据只在本机

原因：用户的阅读、笔记、提醒是私人数据，第一阶段不需要账号和云端。结果：数据保存在本机文件，页面和 AI 共用并自动同步；云端发布流程不属于当前产品入口。

## ADR-19：Agent 驱动，MCP 负责外部工具连接

2026-10-13。产品方向已确定，执行协议尚待实现。补充 ADR-15/18：卡片承载 agent 的工作状态与用户意图；完成、阅读、同步均可交给 agent 处理，外部调用统一使用宿主已有 MCP 或经核验的开源 MCP，不按按钮建设外部应用直连接口，不恢复 legacy 连接器。

Sill 保留本地状态展示和即时反馈；外部成功只能来自真实回执。MCP 不免鉴权，token/OAuth 由宿主或上游处理，Sill 不持有秘密、不另建 OAuth，也不引入连接中间平台。官方托管 MCP 与开源可自托管服务必须区分；不能承诺所有来源都有成熟服务。

代价与边界：需要持久意图、幂等、执行结果关联、冲突保护和异常恢复；当前 local skill/CLI 不具备这些调度能力。在线并发覆盖、虚假连接成功两项 P1 仍未修复。本次文档不会改变实现状态。候选与验收见 [Agent 与 MCP](../implementation/agent-mcp.md)。

## ADR-20：内置助手与对外 MCP 共用能力层

2026-10-13，目标待实现。更新 ADR-15，扩展 ADR-19：Sill既有内置AI助手，也作为MCP服务器提供产品数据/任务操作、助手长任务委托和已安装上游MCP的选择性tools桥接。确定性调用不强制经过内置LLM，复杂任务才委托助手。

安装不等于对外发布；发现和执行都按外部调用方scope、工具允许列表、连接授权与资源所有权限制，委托不得借owner权限提权。上游秘密仅供服务端使用，不能透传给外部agent。保留命名空间/来源、调用链审计、幂等、超时/取消、未知写入结果和循环/深度限制。resources/prompts/订阅等不在默认桥接范围。

当前没有这套内置助手、对外MCP或桥接执行器；旧MCP后端不自动恢复，两个P1仍未修复。接口示意和关闭的发布配置见 [Agent与MCP](../implementation/agent-mcp.md)，本决策不包含服务器选型或部署。

## ADR-21：V1 使用外部助手，接口与部署保持简单

2026-10-13。用户确认 V1 不做内置 AI 助手：Sill 通过配置好的 Webhook 通知 OpenClaw 或 Hermes，外部助手调用 Sill MCP 读写结果。更新 ADR-20 的实施范围：内置助手及上游 tools 桥接留作远期可选，不是首期前置能力。两家官方 Webhook/MCP 能力已核验，但用户 Hermes 的具体产品及实例版本尚未确认，尚未连通。

产品接口候选收敛为内容操作、任务提交/查询/取消（查询含结果）、单对外 MCP 入口；V1 优先内容 metadata 与持久事件记录完成回写，不新增通用 callback 或完整任务调度，具体端点尚未确认。Agent 处理用户意图，确定性数据更新无需再次调用 LLM。采用模块化单体，复用成熟 HTTP/MCP/授权组件；JS 优先候选、Python 备选、云平台和原生客户端均未选定，不因 V1 引入内置 agent runtime 或工作流平台。

代价与边界：仍需事件幂等、有限投递重试、ack 与完成分离、异步结果核对，以及 MCP 调用方最小权限；外部助手不可借 owner 连接提权。当前两个 P1 仍未修复。此次仅维护方案，代码实施须另行确认；候选来源、最小步骤及当前能力以 [统一方案](../implementation/agent-mcp.md) 为准。
