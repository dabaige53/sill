# 手机详情连续展开与阅读关闭

日期：2026-10-24。状态：已采纳。

## 原因

用户反馈资讯向上阅读时，抽屉直接变成全屏，部分位置会卡顿。原实现先切换全屏高度、圆角与安全区，再由 JavaScript 逐帧更新位移；现有测试只检查最终展开状态，没有检查过渡帧。另有三处衔接不一致：关联详情整层淡入淡出、取消拖动时遮罩立即复原、手机读完关闭前恢复正文与工具条。

## 决定

- 手机正文上滑后松手即开始展开，不等待惯性滚动结束；手指按住、多指或系统取消时不改变尺寸。滚轮沿用停稳后展开。
- 目标内容只布局一次，外框用 Motion 的浏览器动画播放位移与圆角裁剪，从当前可见尺寸连续展开或收起。正文不缩放，安全区变化补偿阅读位置，顶部工具与把手随外框接续。过渡期间暂停工具自动显隐；新手势或关闭取消旧过渡。
- 关联详情与普通手机详情都保持不透明，使用现有抽屉时长和曲线。取消下拉或侧滑时，遮罩从当前深度在 `dur-sheet` 内恢复，不立即跳回。
- 读完确认后，手机正文保持当前位移，工具持续隐藏，直接随抽屉退出。已读状态立即保存；阅读中的背景主页更新延后到详情关闭后。桌面仍在收回来源卡片前更新卡面。

沿用已有变量，不增加依赖，不改变已读判定、保存与冲突规则，也不增加系统偏好适配。

## 影响

- 手册：[动效](../../design-system/handbook/motion.md)、[预览与叠放](../../design-system/handbook/card-interaction.md)。
- Web：手机抽屉尺寸过渡、关联详情、取消拖动、读完关闭与背景卡面更新。
- Mac 没有手机抽屉；共有的读完确认与工具隐藏规则保持不变。原生 iOS 阅读界面尚未实现。实测状态见[界面对账表](../product/ui-alignment.md)。
- 本地构建与非浏览器检查不代替 Safari 主屏幕 PWA 的真实手感和帧时间验收。
