# 0056：桌面输入归属与动效职责

日期：2026-10-21
状态：已接受

## 原因

搜索、阅读、菜单与设置分别监听输入，缺少统一的操作层级。滚轮方向过滤早于结束事件判断，导致零位移的结束可能丢失；详情离场的惯性隔离也会拦截新主动输入。不同组件自行等待动画结束，容易产生过期回调。

## 决定

引入 DesktopInteraction，从 Panels、Reader、Shell、CardMenu 和 CardDrag 的现有状态推导输入归属，不另存一份开关状态。搜索、主页快捷键、刷新、阅读手势和 Esc 使用该协调器。系统窗口与附属确认框保留优先权。

WheelPhase 统一主动阶段、惯性和无阶段滚轮的分类。先处理终止事件，再处理方向与位移；触控板不用空闲超时猜测松手。MomentumShield 只消费惯性，主动输入结束隔离。

搜索展示与计算分离：文字立即更新，结果用现有 180ms 参数合并输入，清空及显式切换取消过期任务。瀑布流测量缓存仅在 SwiftUI 子视图或列几何不变时复用。

动效以共享设计变量表达角色：详情入场 280ms、退场 220ms；菜单入场 200ms、退场 160ms。菜单退场独立于按压时长。Web 同步这些角色参数；不变更卡片字号、列数或留白。原生玻璃容器不统一启用 interactive，避免与内部按钮按压同时缩放。

## 边界

不替换 SwiftUI，不引入新的状态库，不实现完整虚拟列表。保留旧系统材质回退和已有 reduceMotion 分支。单元回归验证状态与事件规则；真实性能、帧率和触感仍须由窗口操作及 Instruments 记录确认。
