# 公共 OAuth 应用按账号独立授权

2026-11-03，用户已确认，源码已实现，待迁移与验收。

## 原因

Sill 已按接入应用登记 OAuth 客户端，但同意页还要求每个账号预先具有客户端策略。
因此，用户即使能用账号密码登录，也可能在确认权限前被拒绝。公共应用的接入不应依赖管理员逐个补配账号。

## 决定

- 用 `sill_private.oauth_applications` 保存公共应用的默认策略。管理员按应用登记一次；
  新用户使用自己的 Sill 账号密码登录，再在原同意页确认权限。
- 只有已有 Sill 工作区访问权限的用户能在读取应用策略时建立自己的客户端策略。
  账号、工作区和网页登录权限仍由现有账号流程负责。
- 应用默认策略只初始化缺失记录，不覆盖已有权限、资源限制或停用状态。
  初始化不创建访问 grant；拒绝授权、撤销和再次授权仍走既有流程。
- 已确认的 Muse 和 ChatGPT 固定回调可共用应用登记；新账号默认仅请求个人工作区读取。
  Codex 的本机回调保持原有单独登记方式。
- 访问令牌、刷新令牌、授权版本、卡片权限和资源范围继续按账号隔离。
  不向普通账号开放公共应用表或客户端策略表的直接读写。

## 影响

新增数据库迁移，不改变 Web、Mac 的账号密码登录入口和确认页。
已有授权不变。公共默认策略的修改只影响后续首次接入，既有账号仍使用原策略。
