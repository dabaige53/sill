# 不接入外部来源，内容由助手写入，连接器只用 Composio

2026-10-16，用户已确认，本地代码与界面已按交接授权删除，线上设计尚未同步。取代 [Agent 驱动与 MCP 连接](../implementation/agent-mcp.md) 中旧的「连接选择」「候选清单」，以及 [需求](../agent/PRODUCT.md) 第 6 节旧的「来源与导入」。

Sill 不接入外部来源，也不由程序同步内容。RSS、Readwise、邮件、日历、GitHub 等来源都不连接、不订阅、不导入。卡片内容由助手写入和修改：外部助手通过 Sill MCP 操作；用户保留既有新增卡片、速记等轻入口。文件导入、Markdown 导入和 OPML 导入都从产品中移除。

2026-10-16 补充确认：Agent 优先，界面不提供复杂人工内容编辑器；取消内容编辑不改变其他原有产品设计和轻操作。所有产品数据与状态操作须能由 AI 完成。完整分工见 [Agent 优先与界面边界](../agent/PRODUCT.md#agent-优先与界面边界)。

连接器只有一种：Composio。它只供内置助手操作其他程序。内置助手仍是远期可选，V1 不做。其他外部工作都交给外部助手，由外部助手用自己宿主的工具完成；Sill 不为外部助手提供连接器，也不桥接上游工具。

原因：每个来源都写同步程序、授权和状态检查，工作量大，而且容易把占位状态显示成「已连接」。由助手整理和写入，Sill 只负责展示卡片和表达意图，产品边界更简单。内置助手需要操作其他程序时，统一用 Composio，不再逐个挑选、核验和托管上游 MCP。

代价：

- 不再自建或自选上游 MCP。旧文档中的 Google Calendar、GitHub、Linear、Notion MCP 候选不再采用；这也推翻了旧文档中「不引入 Composio 等连接中间平台」的约定。
- 本地 Web 现有的来源面板、来源授权占位、RSS/OPML、文件导入、首次打开时选来源的界面，以及设置里的来源分组，已按后续交接授权从代码删除。线上设计尚未同步，差异见[删除记录](../records/2026-10-16-remove-sources-import/README.md)，并列入 PR 的 Merge Danger。
- 卡片的来源字段保留，只记录内容来自哪里（例如哪个邮箱、哪个助手），不表示 Sill 已连接该来源。
- Composio 仍需上游授权。秘密留在 Composio 或宿主的安全配置中，不进入卡片、模型上下文、浏览器存储、日志或仓库。
