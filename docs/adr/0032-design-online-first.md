# 设计改动先改线上，再同步线下

2026-10-16，用户已确认，已实施。取代 [ADR 0031](0031-design-md-entry.md) 中「合并后同步线上」的顺序。

设计规则、变量、组件说明和画板先在线上 Design System 和设计画布里改，再同步回仓库的 `design-system/` 和 `design-system/boards/`。线上和仓库不一致时，以线上为准。组件包和图标由仓库代码生成，生成后再发布到线上。

原因：用户在线上画布和 Design System 里看设计、做决定。先改仓库再同步，线上会落后，用户看到的不是最新规则。

代价：每次设计改动多一步同步线下；实现中发现规则要调整时，要先回到线上改，不能只改仓库。仓库里有线上没有的设计改动时，PR 的 Merge Danger 必须写明。

## 本轮仓库模式

2026-10-18，用户明确要求本轮 Web/PWA 交接工作只在仓库内进行。不打开、读取、创建或发布 claude.ai Artifact，不使用 claude.ai 独有工具或 Mobbin 连接器。参考使用公开可访问的产品页面，或用户提供的截图。

本轮先更新仓库 ADR、设计手册、组件说明和画板，再改实现；组件包与图标在仓库生成。画板使用实际页面截图，并维护本地索引。`design-system/design-system.json` 的线上资产记录不改。每个设计 PR 在 Merge Danger 列出线上未同步文件，由用户另行处理；不能声称线上与仓库一致。此范围内以本节和 [Web/PWA 交接](../guides/web-pwa-ui-handoff.md) 为准。
