# Sill 云端插件接入 · 2026-10-15

本次将 Codex 插件从本机卡片技能升级为云端 Sill 客户端。沿用安装 ID `quiet-glass@quiet-glass-local`，显示名称为 **Sill · 窗台**，插件版本为 `0.5.0`。本机旧数据保持原样，插件不再启动本机服务。

## 页面与权限

- 全局侧边栏入口：`sill_open_workspace`；聊天侧栏入口：`sill_open_cards`。两者复用 Sill 云端界面。
- 页面通过 MCP App bridge 调用同一套内容能力，不嵌入网页、不复制账号 Cookie、不直接请求外部网络，也不将账号令牌或卡片写入浏览器持久存储。
- 创建、修改和删除沿用云端版本检查与幂等请求。插件沙箱中的保存按钮直接使用 bridge，避免原生表单被沙箱阻止。
- 生产 Codex 客户端为 public/PKCE，不包含客户端密钥；固定精确本机回调记录在 `deploy/cloud/codex-client.json`。只请求 `openid` 身份范围。
- Sill 授权范围继承生产账号已有的全部内容权限：读取、创建、修改、删除全部卡片。事件与第三方来源没有新增权限或执行目标。
- 授权表、审计、撤销及令牌版本函数由 `supabase/migrations/20261015010603_sill_codex_oauth_consent.sql` 安装。普通网页登录授权保持不变；客户端必须经过独立授权页才取得卡片访问权限。

## 发布与验收边界

自包含 Worker 和校验值在 `deploy/releases/20261015/`。生产变更使用版本上传、核对当前线上版本后再部署，不覆盖现有数据库内容或重建账号。代码回滚版本为 `dff1cfd4-a249-489f-8d9e-bf48bff53948`；回滚前先检查是否已有后续发布。停止插件访问可关闭 Worker 的 `MCP_ENABLE`，保留原网页入口。

自动化检查覆盖 MCP 工具与资源发现、账号权限、撤销后资源不可读、真实 SQL 授权、沙箱握手、创建与编辑、桌面及窄屏、原网页登录与冲突草稿。浏览器测试使用合成账号，不能代替真实 Codex 的账号授权和侧边栏验收。

本机没有 Docker，未运行固定 PostgreSQL 17 容器的并发检查；该检查保留在 CI。生产库安装后检查函数属于非超级用户且无绕过行权限的角色，匿名调用与直接读授权表被拒绝。真实账号的授权、令牌刷新和 Codex 原生侧栏需在部署后分别验证。


## 真实生产授权核验

已在生产启用 OAuth Server、关闭动态客户端注册，登记固定回调的 `Sill · Codex` public/PKCE 客户端，并启用按客户端校验的 Access Token hook。配置没有为其他客户端开放内容权限。

真实 Codex 登录发现提供方的 authorization_id 是不透明字符串，而非 UUID；迁移 `20261015012954_sill_opaque_oauth_authorization_ids.sql` 保留现有值并修正字段与校验。另修正 Worker 请求适配：全局 fetch 通过包装函数调用，手动接收并拒绝重定向，发送提供方 API 版本。错误页只输出固定阶段名与 HTTP 状态，不包含令牌或原始错误。
