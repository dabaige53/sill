## 产品立场

- Agent 优先：已有卡片的正文和结构化内容由 AI 修改；所有产品数据与状态操作须能通过 MCP 完成。不新增复杂人工编辑器。
- 保留阅读、收藏、任务勾选、提醒、归档和设置等轻操作；内容创建与修改按 [PRODUCT.md](../../docs/agent/PRODUCT.md) 的职责边界处理。
- 信息流就是入口：不放侧边栏、横幅或统计面板。手机主页顶部只有 Sill 页名、头像和一排分栏胶囊，往下读时收起（见「手机主页」）；桌面顶栏只有品牌图标、Sill、搜索栏和头像，分栏收进 Sill 后的菜单（见「桌面顶栏与 AI 框」）。
- 工具按需出现：靠近、选择、提起卡片时才浮现，用完就退场。
- Agent 驱动内容与执行；卡片展示状态、收集意图。涉及外部动作时由 agent 通过 MCP 执行并回写，不逐按钮直连外部应用；打开原文仍可作为显式导航。
- 本地反馈与外部完成分开：待处理、执行中、失败和结果未知必须可辨认。意图调度尚待落地，见 [架构边界](../../docs/implementation/agent-mcp.md)。
- 新内容不插队：正在读的位置不动，新卡在顶部等着。
- 当前产品以账号云端工作区为共同数据源；独立本地模式用于开发与测试，不与账号双向同步。设备通知设置留在设备上。外部备份与提醒边界见 [ADR 0065](../../docs/adr/0065-account-backups-and-device-reminders.md)。
- 退出不用找 X：点外面、按 Esc、下拉、读完上推都能离开。

## 主屏幕启动


## 文案

文案按职责维护在 `copy/zh-Hans/*.json`；`copy/zh-Hans.json` 是供 Web、Apple 和构建脚本读取的生成文件。设计变量按类别维护在 `tokens/*.json`，生成兼容文件 `tokens.json`。修改源文件后运行 `npm run contracts:generate`，不得直接修改兼容文件。拆分不改变 key、变量角色或已有值。

- 界面只保留操作、必要说明和需要用户处理的提示，不放宣传语、开发备注或内部实现说明。设置项须控制实际行为；尚未实现的能力不展示开关。卡片中的用户正文与备注不受此规则影响。
- 按钮写要去做的事：「加入」「审阅」「回复」「值机」「放回桌面」。例外：待办和提醒前面的圆圈就是「完成」，不另放文字按钮；读屏读作「完成」或「恢复」。
- 不写状态句：「已是最新」「加载中」「到底了」「已读」「已经结束」都不说，交给动作和颜色。
- 每个图标按钮都有中文 `aria-label`。

## 现有数值的变量维护

- C4 只提取现有数值，不改变界面。`fixed-*` 保存不随主题变化的既有颜色，包括实色按钮上的白色、照片背景和封面色值。
- 通用内部间距使用 `space-*`；已有明确角色的卡片内边距、积木间距、触控尺寸和圆角继续使用原变量。几何尺寸与动效数值不因数值相同而误用间距变量。
- 动效的 `motion-*` 是内部状态变量。组件沿用设计变量定义的过渡、曲线与填充方式。跟手、工具条与镜片保留各自原有的状态优先级。
- 删除选择器前，全仓核对模板、脚本、组件和测试引用。移动只调位置；变量替换和优先级清理另作提交，并对照三种宽度的真实页面截图。

## 颜色

- 文字：标题和正文用 `ink`，摘要、元信息、说明和占位文字用 `muted`（三种底上都过 4.5:1）。`secondary` 只给图标和分隔符用。
- 日程相对时间使用 `muted`，具体开始时间使用 `ink`；链接、焦点和操作继续使用蓝色。
- `accent` 是唯一的动作色。一个区域里只出现一个 `accent` 实心按钮，留给提交那一下（「存」「保存」「完成」「去原文」）。
- 选中状态不用蓝：设置分类是浮起的白行，筛选胶囊是 `ink` 实底配 `card` 字，分段控件是白色滑块。开关打开用 `toggle-on`（与 `accent-fill` 同一个蓝），不用系统绿。
- 标签胶囊和卡片内的次级色块用 `surface`，不用 `accent-soft` 浅蓝底。
- 状态胶囊：琥珀用 `alert-soft` 底配 `alert` 字，完成用 `success-soft` 底配 `success` 图标。
- 遮罩：预览、抽屉和面板用 `dim`，只压暗、不模糊，页面靠明暗后退。搜索页面用 `canvas`；多选菜单用 `frost` 加 blur(28px) saturate(1.6)，是磨砂材质，不压暗。
- 品牌色 `sky`、`sky-soft`、`ledge`、`ledge-deep` 只用于图标、封面和启动画面，不进界面。

## 玻璃

- Mac App 在 Info.plist 声明 `UIDesignRequiresCompatibility`，系统按兼容外观绘制，不启用 Liquid Glass 新外观；与 Web 观感及性能保持一致。以下玻璃调用保留，按兼容外观呈现。



- 玻璃是一块清透的镜片：`glass` 填充（浅色 38% 白），`glass-filter` 即 blur(12px) saturate(1.9) brightness(1.06)，让下面的颜色透上来；左上一道 `glass-edge` 亮边，右下一道 `glass-shade` 弱边，外圈 0.5px `glass-rim` 发丝线，阴影 `shadow-glass` 宽而淡。不靠白底加厚阴影冒充玻璃。
- 用在：底部导航胶囊、详情与阅读页的底部工具条、阅读页右上的按钮组、多选条、Toast、下拉刷新圆环。多选菜单字多，用更实的 `glass-thick`；桌面 AI 框、多选条和详情工具条用同一块清透玻璃（`glass` 加 `glass-filter`），与 macOS 原生 regular 玻璃对应。卡片菜单盖在卡片文字上，用 `card` 实底。
- 手机（≤650px）底部胶囊暂不使用模糊：导航胶囊、多选条、详情底部工具条和 Toast 用 `glass-thick` 底，保留亮边、发丝线与阴影。iOS 在页面开始或停止缩放、胶囊淡入时重建模糊，胶囊会闪一下或在最后一帧变色。桌面与手机顶栏保留玻璃。
- macOS 26 及以上的详情关闭、全屏使用原生玻璃圆片；Web 的详情顶部关闭、全屏是浮起的白色圆片：`card` 底、0.5px `line-card`、`shadow-float`，不是灰色实心圆。
- 工具条下方有滚动边缘：内容在工具条下面渐隐，图标不和正文抢；底部工具条收起时边缘一起退场；顶部边缘在滚动后常驻，不随顶部工具收起。
- 浏览器不支持模糊时回退到 `card` 实底加 1px `line-hover` 描边。

## 品牌字标

- 品牌展示保留 `Sill` 大小写，使用 Georgia 衬线字体、正常字重与 -0.02em 字距。顶栏、手机首页、欢迎页及现行品牌画板保持一致。
- 颜色和字号沿用所在位置，保留品牌图标与入口动作。Web 未安装 Georgia 时使用 Times New Roman 或系统衬线字体；Mac 使用 Georgia。正文与系统名称继续沿用原字体。

## 字体

- 系统字体栈 `sans`；数字统一用 `rounded`（圆体）并开启 tabular-nums。
- 字号在 CSS 中写作 `--text-<样式名>`，例如 `--text-card-title`、`--text-meta`。`caption` 12、`meta` 13、`control` 14、`body` 15 同时充当小字阶梯：数值相同的文字直接用它们，不另写像素。
- 桌面卡片标题、摘要和要点不限制行数。以下行数约束仅用于手机。
- 卡片（A 字号）：`card-title` 16/22、600，最多 2 行；`summary` 14/22，最多 3 行（有封面也是 3 行；手机文章和邮件 4 行，笔记和汇总 2 行，建议原因 1 行；写入 50–60 字），卡上的要点同为 14/22；卡片头部 `card-meta` 12/18。卡片字号只用于卡片，不套用到详情或阅读页。
- 手机起点：手机宽度下，卡片与详情内容文字乘 `text-phone-scale` 1.07，约为卡片标题 17、摘要 15、头部 13；预览正文与阅读页同为 `reader-body` 17。设置里的卡片、阅读文字大小在此基础上相乘，三端共用同一项设置。导航、标签页、工具条与按钮不乘，桌面 Web 与 Mac 为 1（[ADR 0068](../../docs/adr/0068-phone-text-scale.md)）。
- 大号输入：搜索框、AI 输入框、拖放提示与搜索分类用 `input` 17，不借用卡片标题字号。
- 主角数字：`figure` 34，详情页用 `figure-xl` 44，航段用 `figure-route` 28。
- 金句：`quote` 21/500，最多 4 行。
- 阅读：资讯以外类型的全屏阅读沿用 `reader-title` 与 `reader-body`。
- 卡片详情与阅读以 `CardTypeDetails`、`CardTypeMobile`、`CardTypeReading` 画板为准：预览标题 26、600、行高 1.3，正文 15（手机 17）、行高 1.75；卡面摘要只用于卡面与搜索，详情的导语和列表属于正文，不自动插入摘要；全屏与预览共用字号：桌面标题 26、正文 15，手机沿用预览字号；放大和缩小只调整布局，不切换文字大小。左右留白 30（手机 20），正文不截断；资讯放大正文列最大宽度为 `reader-column` 800，预览不变。资讯预览与放大都先封面，再来源、标题、标签，再接正文；上下间距见[纵向间距](content-layout.md#纵向间距)。`ArticleReading` 保留旧版排版比较，不作为当前实现依据。


## 卡片积木


卡片由 6 组、29 块积木拼成，类型只是配方。

| 组 | 积木 |
|---|---|
| 头部 | 来源、人、状态、提示 |
| 媒体 | 封面、原图、拼图、节目条、文件条、地图、波形 |
| 文字 | 标题、摘要、要点、金句、正文、代码 |
| 数据 | 大数字、趋势线、进度条、时间段、航段 |
| 列表 | 勾选清单、引用卡、附件、参与者、检查项、时间列表 |
| 动作 | 按钮（一个或两个） |

- 顺序固定：贴顶媒体（封面、原图、拼图）→ 头部 → 主角 → 文字与数据 → 条状媒体 → 列表 → 动作。
- 只有一个主角：标题、金句、大数字、时间段、航段里只能有一个最大。
- 限额：头部 1、媒体 1、文字 2、数据 2、列表 1、动作 1，总共不超过 6 块。
- 按钮到点才出现：会议开始前 15 分钟出现「加入」，PR 等你审阅时出现「审阅」；平时卡面上没有按钮。
- 窄于 300px 时收起：摘要变 1 行，参与者只留头像，双按钮上下排。
- 10 类、32 种预设，见设计画布第 21–23 块。

## 文字长度

- 卡片和详情内的列表保持既定列宽。文件行与关联入口在各自宽度内省略，保留图标和进入箭头；正文和详情标签允许换行，长单词在边界内断开。会议名称与会议码分行完整显示。PR 增删数量各自保持完整，空间不足时分行；播客收起条的次行在自身宽度内省略。
- 桌面卡片文字自然换行，高度随内容增长；不按行数截断标题、摘要和要点。摘要统一最多显示 120 个文字字符，手机与桌面均自然增高；以下 `lines-*` 规则不用于摘要，其他手机截断用「…」。
- 汇总卡面使用短摘要；完整内容与列表放在详情正文中，不在卡面另外叠放编号要点。
- 汇总卡展示助手写入的卡面摘要，不由界面替换为固定周统计。正文只作缺少摘要时的预览，详情保留完整原文；正文列表沿用正文的字号与颜色，不使用带圆底的独立编号。
- 待办预览优先显示未完成事项，再显示已完成事项，清单全部展示，不显示“另有 N 项”；新待办每卡最多六项，更多按事项拆卡，历史超量清单保留内容与状态，另行整理。完成数量按完整清单计算。勾选后保留当前预览行与卡片位置；离开卡片也不重排，直到主动刷新或更换排序方式，避免下一次空格激活另一动作。空清单不显示全部完成。

## 图标

- 24×24 线性图标，round cap 和 join，颜色跟随 `currentColor`。三档：S16 描边 2.0、M20 描边 1.8、L24 描边 1.65。
- 一个图标只表达一个意思：主页用房子，AI 用对话气泡，头像占位用人像，设置分类里用齿轮，稍后读用眼镜，在 Sill 内再提醒用方圆秒表（`snooze`），回复用折回箭头（`reply`），时刻用时钟，提醒用铃铛，免打扰用划线铃铛，导航用 chevron。
- 资讯、笔记、建议、邮件、视频、播客的品牌无法识别时，用来源类型的通用线条图标放进圆标；类型也未知时用链接图标，不显示首字、不退回书本。待办、日程、提醒、汇总、文件、照片有可识别品牌时用来源圆标，否则保留卡片类型图标。

### 文字和图标只用一种

一个控件要么只写文字，要么只放图标，不要两样同时出现，表达同一个意思。

- **图标按钮不带文字**：工具栏（包括详情底部胶囊里的回复、去原文、加入）、全局工具、关闭、全屏只放图标，含义写在中文 `aria-label` 里。
- **菜单项、设置分类、筛选胶囊、引导页选项**：只写文字。用户确认的局部例外：多选卡片上下文菜单采用文字左、既有动作图标右的紧凑布局，详见 [SelectionBar](../components/SelectionBar/README.md)。
- **允许同时出现的情况**：图标和文字说的是两件不同的事。比如卡片头部「来源圆标 + 发布方或作者」、附件「文件类型图标 + 文件名」、引用行「卡片类型图标 + 标题」。图标表示类型，文字是具体名称。
- **输入框**：前置的搜索放大镜可以和占位文字同时出现，它标的是输入框的类型，不是按钮的含义。
- 判断方法：遮住图标，文字是否已经把意思说全？说全了，图标就是重复，应该去掉。反过来，遮住文字也一样。
- 图标在 24 格里尽量方正，不画成扁条：`sill` 两张卡立起来占 19×14.5，`mail`、`folder` 占 18×16，`video` 占 19×16。
- 卡片操作的九个图标（`bookmark`、`tag`、`glasses`、`reply`、`external`、`snooze`、`bell-off`、`video`、`download`）画成圆润方形：外框用约 4px 圆角的方块，整体占 16–17 格见方，眼镜和摄像机按物体比例略扁；不画内部短线，选中填色后不丢细节。其余图标保持原样（[ADR 0090](../../docs/adr/0090-tag-layer-and-rounded-action-icons.md)，部分替代 [ADR 0037](../../docs/adr/0037-card-detail-toolbar.md) 与 [ADR 0038](../../docs/adr/0038-keep-original-icons.md)）。导航当前项保留镜片，见 [ADR 0039](../../docs/adr/0039-keep-navigation-lens.md)。
- `assets/Icons/` 的 SVG 由 `apps/web/atoms/icons.ts` 生成，和页面实际使用的一致。完整图标见 `IconSet` 画板。

## 使用组件

- 组件示例由产品代码生成，加载顺序为 `tokens.css`、`components/bundle.css`、`components/bundle.js`（`window.Sill`）。
- macOS 原生端使用 SwiftUI 与 AppKit，不嵌入网页。视觉、状态与动效对齐 Web，见 [设计约束](../../docs/agent/DESIGN.md)「Web 与 macOS 一致」。原生实现的视觉与交互须在实际窗口验收。
- 专门的无障碍设置与系统偏好适配不在项目范围内。
