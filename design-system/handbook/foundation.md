# 基础与组件

[返回设计手册](../README.md)。

## 产品立场

- Agent 优先：已有卡片的正文和结构化内容由 AI 修改；所有产品数据与状态操作须能通过 MCP 完成。不新增复杂人工编辑器，不把接口字段逐项搬到界面。
- 用户保留既有新增卡片、记一笔等轻入口，其他原有产品设计与轻操作保持不变。取消内容编辑不授权删除阅读、收藏、任务勾选、提醒、归档或设置等功能。具体边界见 [产品约定](../../docs/product/agent-mcp.md#agent-优先与界面边界)。
- 信息流就是入口：不放侧边栏、横幅或统计面板。手机主页顶部只有 Sill 页名、头像和一排分栏胶囊，往下读时收起（见「手机主页」）；桌面顶栏只有品牌图标、Sill、搜索栏和头像，分栏收进 Sill 后的菜单（见「桌面顶栏与 AI 框」）。
- 工具按需出现：靠近、选择、提起卡片时才浮现，用完就退场。
- Agent 驱动内容与执行；卡片展示状态、收集意图。涉及外部动作时由 agent 通过 MCP 执行并回写，不逐按钮直连外部应用；打开原文仍可作为显式导航。
- 本地反馈与外部完成分开：待处理、执行中、失败和结果未知必须可辨认，不能只用动效或颜色暗示成功。意图调度尚待落地，见 [架构边界](../../docs/product/agent-mcp.md)。
- 当前宿主明确支持发送消息时，卡片详情提供「与助手讨论」，携带当前卡片引用交给宿主助手；只有宿主确认收到后才结束交接。独立网页或不支持消息的宿主不显示交接入口；不提供复制引用或剪贴板降级。照片页的错误提示参与纵向布局，不遮住缩略图与动作。交接不表示卡片已经修改，不新增内置聊天界面、执行队列或上游连接。
- 新内容不插队：正在读的位置不动，新卡在顶部等着。
- 本机是默认：卡片状态保存在本机；agent、模型与 MCP 的实际执行位置取决于宿主和上游配置，不承诺所有 AI 处理都在本机。
- 退出不用找 X：点外面、按 Esc、下拉、读完上推都能离开。

## 主屏幕启动

云端独立网页从 iPhone／iPad 主屏幕启动时使用 standalone 模式，不显示 Safari 地址栏。沿用 Sill 图标、浅色背景和现有安全区／键盘布局；保留系统状态栏。普通 Safari 标签页仍由浏览器管理工具栏，不通过脚本强行隐藏。此配置不改变 macOS 原生端或 MCP 内嵌页，也不新增离线缓存。

## 文案

文案按职责维护在 `copy/zh-Hans/*.json`；`copy/zh-Hans.json` 是供 Web、Apple 和构建脚本读取的生成文件。设计变量按类别维护在 `tokens/*.json`，生成兼容文件 `tokens.json`。修改源文件后运行 `npm run contracts:generate`，不得直接修改兼容文件。拆分不改变 key、变量角色或已有值。

- 简体中文，短句，陈述事实，不感叹，不用 emoji。
- 按钮写要去做的事：「加入」「审阅」「回复」「值机」「放回桌面」「撤销」。例外：待办和提醒前面的圆圈就是「完成」，不再另放文字按钮；读屏读作「完成」或「恢复」。
- 不写状态句：「已是最新」「加载中」「到底了」「已读」「已经结束」都不说，交给动作和颜色。
- 每个图标按钮都有中文 `aria-label`。

## 现有数值的变量维护

- C4 只提取现有数值，不改变界面。`fixed-*` 保存不随主题变化的既有颜色，包括实色按钮上的白色、照片背景和封面色值；不能换成会随主题变化的 `card` 或 `ink`。
- 通用内部间距使用 `space-*`；已有明确角色的卡片内边距、积木间距、触控尺寸和圆角继续使用原变量。几何尺寸与动效数值不因数值相同而误用间距变量。
- 动效的 `motion-*` 是内部状态变量。组件沿用设计变量定义的过渡、曲线与填充方式。跟手、工具条与镜片保留各自原有的状态优先级。
- 删除选择器前，全仓核对模板、脚本、组件和测试引用。移动只调位置；变量替换和优先级清理另作提交，并对照三种宽度的真实页面截图。

## 颜色

- 页面底色用 `canvas`，卡片和弹层用 `card`。内容卡片不换底色，也不加彩色左边条。
- **已读未读只靠卡片颜色**：未读是 `card` 加 `shadow`，在背景上浮起来；已读退成 `card-read`，边框换成 `line-read`，去掉阴影，标题换成 `muted`，封面降饱和到 0.6，过渡 `dur-read`。不加蓝点，不写「已读」，也不加「✓」等符号，见 [ADR 0030](../../docs/adr/0030-read-state-color-only.md)。只有资讯、消息、笔记、媒体、整理五类分已读未读。日程结束后同样退成已读色，开始时间也换成 `muted`，不写「已经结束」。完成的待办与提醒也使用同一退色，不从主页移除；工单、项目、指标保持原有状态表达。悬停和点击后仍保留已读底色，不能重新变成未读白卡。浅色已读底色为 #e9e9ee，深色为 #121215，标题仍使用可读的 muted。
- 文字：标题和正文用 `ink`，摘要和元信息用 `muted`（三种底上都过 4.5:1）。`secondary` 只给图标和分隔符用。
- `accent` 是唯一的动作色。一个区域里只出现一个 `accent` 实心按钮，留给提交那一下（「存」「保存」「完成」「去原文」）。
- 待办和提醒的圆圈用 `accent` 描边，表示可以点；完成后是 `accent-fill` 实心加白勾。圆圈只改 Sill 里的状态，不表示来源里已经完成；以后由 agent 把这个状态同步回来源。
- 选中状态不用蓝：设置分类是浮起的白行，筛选胶囊是 `ink` 实底配 `card` 字，分段控件是白色滑块。开关打开用 `toggle-on`（与 `accent-fill` 同一个蓝），不用系统绿。
- 标签胶囊和卡片内的次级色块用 `surface`，不用 `accent-soft` 浅蓝底。
- 状态胶囊：琥珀用 `alert-soft` 底配 `alert` 字，完成用 `success-soft` 底配 `success` 图标。
- 遮罩：预览、抽屉和面板用 `dim`，只压暗、不模糊，页面靠明暗后退。搜索页面用 `canvas`；多选菜单用 `frost` 加 blur(28px) saturate(1.6)，是磨砂材质，不压暗。
- 品牌色 `sky`、`sky-soft`、`ledge`、`ledge-deep` 只用于图标、封面和启动画面，不进界面。

## 玻璃

- macOS 26 及以上：顶部搜索框、账户按钮、底部 AI 输入栏、阅读工具栏、阅读右上按钮组、预览关闭与放大按钮、多选栏、刷新圆环、新内容提示和 Toast 使用系统 Liquid Glass（regular；仅独立账户按钮启用 interactive，内部已有按压反馈的容器不启用）。搜索与账户、预览右上按钮分别共用 GlassEffectContainer；顶栏不铺实色底，不叠加自绘玻璃描边或阴影。搜索焦点环及拖入卡片的强调色保留。旧系统回退 Sill 玻璃。Web 保留既有材质，不模拟系统折射；尺寸、文案、状态和操作保持一致。

- macOS 适配：macOS 的视觉、状态与动效以 Web 为准，保留 Sill 的信息结构、卡片构图、字号层级、留白与主窗口内阅读。卡片保持不透明，不加玻璃。设置不另开系统窗口，和 Web 桌面一样在主窗口中央打开设置弹窗（见[网页交互](web-interaction.md#设置弹窗)）。适配与性能优化不授权改变导航、功能流程或重新设计卡片。


- 两层：卡片、正文、封面是内容层，用不透明的 `card`；浮在上面的工具是功能层，用玻璃。玻璃不放进卡片，也不叠在玻璃上。
- 玻璃是一块清透的镜片：`glass` 填充（浅色 38% 白），`glass-filter` 即 blur(12px) saturate(1.9) brightness(1.06)，让下面的颜色透上来；左上一道 `glass-edge` 亮边，右下一道 `glass-shade` 弱边，外圈 0.5px `glass-rim` 发丝线，阴影 `shadow-glass` 宽而淡。不靠白底加厚阴影冒充玻璃。
- 用在：底部导航胶囊、详情与阅读页的底部工具条、阅读页右上的按钮组、多选条、Toast、下拉刷新圆环。多选菜单字多，用更实的 `glass-thick`。卡片菜单盖在卡片文字上，用 `card` 实底。
- macOS 26 及以上的详情关闭、全屏使用原生玻璃圆片；Web 的详情顶部关闭、全屏是浮起的白色圆片：`card` 底、0.5px `line-card`、`shadow-float`，不是灰色实心圆。
- 工具条下方有滚动边缘：内容在工具条下面渐隐，图标不和正文抢；工具条收起时边缘一起退场。
- 浏览器不支持模糊时回退到 `card` 实底加 1px `line-hover` 描边。

## 字体

- 系统字体栈 `sans`；数字统一用 `rounded`（圆体）并开启 tabular-nums。
- 字号在 CSS 中写作 `--text-<样式名>`，例如 `--text-card-title`、`--text-meta`。`caption` 12、`meta` 13、`control` 14、`body` 15 同时充当小字阶梯：数值相同的文字直接用它们，不另写像素。
- 卡片（A 字号）：`card-title` 16/22、600，最多 2 行；`summary` 14/22，最多 3 行（有封面也是 3 行；手机一律 2 行；写入 50–60 字），卡上的要点同为 14/22；卡片头部 `card-meta` 12/18。卡片字号只用于卡片，不套用到详情或阅读页。
- 大号输入：搜索框、AI 输入框、拖放提示与搜索分类用 `input` 17，不借用卡片标题字号。
- 主角数字：`figure` 34，详情页用 `figure-xl` 44，航段用 `figure-route` 28。
- 金句：`quote` 21/500，最多 4 行。
- 阅读：资讯以外类型的全屏阅读沿用 `reader-title` 与 `reader-body`。
- 资讯阅读（B 均衡）：只用于资讯卡，预览浮层与全屏阅读页相同。`article-title` 22/30、600；`article-section` 17/24、600，上方 28、下方 12；`article-body` 15/25、400，用于正文、列表和引用；`article-meta` 12/18，用于来源、日期和图注，`secondary` 色。系统字体，正常字距，左对齐，无首行缩进；正文完整显示，不截断。示例与布局见 `ArticleReading` 画板。

## 卡片积木

字段展示遵循 ADR 0050：缺失表示未知，省略对应内容，不补零或借用其他字段。邮件的发件人与头像只取 `sender`，来源只取 `sources`，收件人只取 `recipients`，不默认「发给你」。媒体只在 `duration` 存在时显示总时长，真实零秒仍显示；阅读 `progress` 不表示播放位置。正文只用于阅读，`chapterCount` 只表示已知章节总数；没有真实播放能力时，不显示模拟播放、片段步骤或写入播放进度。此处落实已有字段职责，沿用既有卡片布局、设计变量和轻操作规则。

卡片由 6 组、29 块积木拼成，类型只是配方。

| 组 | 积木 |
|---|---|
| 头部 | 来源、人、状态、提示 |
| 媒体 | 封面、原图、拼图、节目条、文件条、地图、波形 |
| 文字 | 标题、摘要、要点、金句、正文、代码 |
| 数据 | 大数字、趋势线、进度条、时间段、航段 |
| 列表 | 勾选清单、引用卡、附件、参与者、检查项、时间列表 |
| 动作 | 按钮（一个或两个） |

- 顺序固定：贴顶媒体（封面、原图、拼图）→ 头部 → 主角 → 文字与数据 → 条状媒体 → 列表 → 动作。
- 只有一个主角：标题、金句、大数字、时间段、航段里只能有一个最大。
- 限额：头部 1、媒体 1、文字 2、数据 2、列表 1、动作 1，总共不超过 6 块。
- 按钮到点才出现：会议开始前 10 分钟出现「加入」，PR 等你审阅时出现「审阅」；平时卡面上没有按钮。
- 窄于 300px 时收起：摘要变 1 行，参与者只留头像，双按钮上下排。
- 10 类、32 种预设，见设计画布第 21–23 块。

## 文字长度

- 卡上按行数截，写入时按字数限（`lines-*` 令牌）。截断统一用「…」。
- 总结过长时不在卡上堆一段话，改写成「一句结论 + 最多三条要点」，完整内容在点开后看。
- 摘要卡展示助手写入的摘要与要点，不由界面替换为固定周统计。正文只作缺少摘要时的预览，详情保留完整原文；列表和长单词不能撑破卡片。
- 待办预览优先显示未完成事项，再显示已完成事项，最多三项；完成数量仍按完整清单计算。键盘焦点在任务列表内时暂时保留正在操作的任务位置，离开卡片后再排序，避免下一次空格激活另一动作。空清单不显示全部完成。

## 间距与尺寸

- 卡片内边距 `card-padding` 18（手机 `card-padding-sm` 16），积木之间 `block-gap` 8，封面内缩 `cover-inset` 8。
- 信息流间距：手机 `gap-sm` 12、中等宽度 `gap-md`、桌面 `gap`；页边距对应 `margin-sm` 16、`margin-md`、`margin-lg`。
- 列数按 `col-ideal` 向下取整，并保证最小列宽 `col-min`；桌面不设四列上限，宽度足够时继续增加到五列、六列或更多。信息流列宽均分可用空间，两侧各留 12px，与顶栏对齐。
- macOS 新窗口默认宽 1512、高 760，标准密度下显示四列；已有窗口保留系统记录的尺寸，调整窗口后按可用宽度重新排列。
- 紧凑、标准、宽松的理想列宽分别为 280、340、400，取值见 `density`。资讯和邮件的纯文字摘要最多四行；其他卡片紧凑摘要最多两行、其他密度最多三行。详情不受此截断规则影响。
- 来源头部已经为更多按钮预留空间，任务数量和到期提示在悬停或键盘聚焦时仍保持可见。手机卡片上没有更多按钮，不留这块空白，文字写到卡片右边缘。
- 所有可点击元素不小于 `hit-target`。例外：手机待办预览每项高 28，满足 WCAG 2.2 的 24 最小值；其中的圆圈向外扩到 44 宽。
- 资讯阅读：正文最大宽度 `article-measure` 600，居中；左右内边距 `article-gutter` 32（手机 `article-gutter-sm` 20），容器最大 664。段间距 16，标题下方 24，来源行下方 14，列表项间距 6，引用左侧 2px 细线、缩进 18。不缩放整页。
- 圆角：卡片 `card-radius` 22（手机 `card-radius-sm` 16）、封面 `cover-radius` 14、弹层 `sheet-radius` 28、面板 `panel-radius` 24、控件 `control-radius` 12、胶囊 `pill-radius` 999。CSS 变量与令牌同名，例如 `--cover-radius`。

## 图标

- 24×24 线性图标，round cap 和 join，颜色跟随 `currentColor`。三档：S16 描边 2.0、M20 描边 1.8、L24 描边 1.65。
- 一个图标只表达一个意思：主页用房子，AI 用对话气泡，头像占位用人像，设置分类里用齿轮，稍后读用眼镜，在 Sill 内再提醒用方圆秒表（`snooze`），回复用折回箭头（`reply`），时刻用时钟，提醒用铃铛，免打扰用划线铃铛，导航用 chevron。
- 不用 emoji，不用 icon font，不用品牌标志；来源用通用图标加来源名表示。

### 文字和图标只用一种

一个控件要么只写文字，要么只放图标，不要两样同时出现，表达同一个意思。

- **文字按钮不带图标**：「在浏览器中授权」「放回桌面」「为什么看到」只写字。不加 ↗ 外链箭头，也不加前置图标。
- **图标按钮不带文字**：工具栏（包括详情底部胶囊里的回复、去原文、加入）、全局工具、关闭、全屏只放图标，含义写在中文 `aria-label` 里。
- **菜单项、设置分类、筛选胶囊、引导页选项**：只写文字。用户确认的局部例外：多选卡片上下文菜单采用文字左、既有动作图标右的紧凑布局，详见 [SelectionBar](../components/SelectionBar/README.md)。
- **允许同时出现的情况**：图标和文字说的是两件不同的事。比如卡片头部「来源类型图标 + 来源名」、附件「文件类型图标 + 文件名」、引用行「卡片类型图标 + 标题」。图标表示类型，文字是具体名称。
- **输入框**：前置的搜索放大镜可以和占位文字同时出现，它标的是输入框的类型，不是按钮的含义。
- 判断方法：遮住图标，文字是否已经把意思说全？说全了，图标就是重复，应该去掉。反过来，遮住文字也一样。
- 图标在 24 格里尽量方正，不画成扁条：`sill` 两张卡立起来占 19×14.5，`mail`、`folder` 占 18×16，`video` 占 19×16。
- 线条积木（ADR 0037）：从 Sill 标志里取三个元素。外形用 2–2.5px 圆角方块，少用圆形和尖角；需要底座时画一条贯穿的地平线（窗台），如下载、停止提醒；小细节用一段「窗」短线，如收藏条上的短线、标签的孔。线宽和档位不变。已按此重画：`bookmark`、`tag`、`glasses`、`reply`、`external`、`snooze`、`bell-off`、`video`、`download`。
- 保留当前全部图标，见 [ADR 0038](../../docs/adr/0038-keep-original-icons.md)。上述九个保持现状，其余图标不重画，也不统一为方圆轮廓。导航当前项保留镜片，见 [ADR 0039](../../docs/adr/0039-keep-navigation-lens.md)。
- `assets/Icons/` 的 SVG 由 `apps/web/atoms/icons.ts` 生成，和页面实际使用的一致。完整图标见 `IconSet` 画板。

## 使用组件

- 组件示例由产品代码生成，加载顺序为 `tokens.css`、`components/bundle.css`、`components/bundle.js`（`window.Sill`）。
- macOS 原生端使用 SwiftUI 与 AppKit，不嵌入网页。视觉、状态与动效对齐 Web，见 [设计约束](../../DESIGN.md)「Web 与 macOS 一致」。原生实现的视觉与交互须在实际窗口验收，不能以源码合并或构建通过代替。
- 专门的无障碍设置与系统偏好适配不在项目范围内。
