# 网页阅读与辅助交互

## 资讯阅读

只用于资讯卡；预览与全屏分别遵循 `CardTypeDetails`、`CardTypeMobile`、`CardTypeReading`，Web 与 macOS 对齐。数值见[字体](foundation.md#字体)与[间距与尺寸](foundation.md#间距与尺寸)。

- 预览顺序：封面 → 来源 · 日期 · 阅读时长 → 标题 → 标签 → 正文 → 备注。标题区与正文之间不加通栏分隔线，保留原有留白。全屏把封面移到标题区之后。导语与列表属于正文，不额外插入卡面摘要。日期只在来源行出现一次，写「今天」「昨天」「10/18」，跨年加年份；取发布日期，没有时取保存日期，再没有时取卡片时间。
- 预览浮层宽度不变，左右 30（手机 20）。资讯放大正文最大宽度为 `reader-measure` 920，桌面左侧目录宽 `reader-outline-width` 160，可收起进入专注阅读。目录只取正文 Markdown 的真实标题，不列「文章开头」；无标题时不显示目录。目录标题用 body 15px、中等字重、ink；条目用 control 14px，普通项为 muted，当前位置为 accent 与 600 字重，实际子标题缩进。点击按 base 时长与 ease 曲线滚动，手动滚动同步当前位置，键盘跳转即时。手机预览提供可展开的「目录」。
- 资讯、播客和视频的预览保留底部操作胶囊；放大后操作直接显示在左上角，缩小与关闭在右上角。顶部占位 space-64，正文底部 space-24，不铺上下渐隐。阅读进度、读完圆环与既有轻操作保留。进度条与圆环随滚动逐帧更新；进度本身最多每 500ms 保存一次，关闭详情、切到后台或离开页面时补存；读完立即保存。视频宽屏播放器与文字区为 1.6:1，播客等宽，左右独立滚动；窄屏上下排列。参见 [ADR 0065](../../docs/adr/0065-expanded-reading-layout.md)。
- 其他类型的预览与阅读页不使用资讯阅读变量。

## 桌面阅读与操作细节

- 键盘打开搜索、记一笔及详情时立即显示并聚焦，关闭也立即响应；点击和触摸保留已有空间过渡。手机详情正文与抽屉同时出现，不再单独等待 200ms。
- 卡片内容块沿用 HTML 参考稿，来源、标题、摘要、清单、附件和关联内容之间统一间隔 8px。邮件附件使用 `surface` 底的静态标签，间隔 6px、内边距 6px 10px；没有链接时不添加点击操作。
- 桌面待办文字最多两行，圆圈与首行对齐。全部完成后保留原有清单结构和可恢复的勾选项，仅改变完成色，不压缩成完成横条。
- 建议卡显示两个关联预览；更多关联以“另有 N 项关联内容”说明，完整关联仍在详情查看。
- 短待办、提醒及短笔记预览保留较窄面板；普通卡片详情的桌面左右内边距为 30px，全屏时占满剩余宽度。资讯预览采用相同内边距，放大页正文宽度和目录按「资讯阅读」。短内容末尾到工具条保持清晰分隔，不添加多余空白。
- macOS 搜索与 Web 使用相同分类入口与按需展开的状态、标签筛选；标签完整显示，各行可横向滚动。Toast 采用同一暂停规则。
- 桌面卡面不显示更多按钮，头部不预留按钮空位，日期与完成数量靠右对齐；右键或 Shift+F10 打开卡片菜单，VoiceOver 保留菜单动作。
- 资讯和邮件的纯文字摘要以 50–60 字为内容目标，桌面完整显示并自然增高，手机最多显示 4 行；正文依据不足时不凑字。已有要点版和展开叠卡沿用原规则，其他类型不变。
- 桌面预览工具栏与 AI 框、多选条使用同一种玻璃，按钮为 44，间距 4，胶囊高 60；两端沿用同组阴影。文字提示与圆形悬停底色保留。
- 指针（Web 与 macOS 一致）：可点击的按钮、链接、卡片和输入框里的标签、清除、移除按钮悬停显示手形；搜索框和 AI 框整个胶囊显示文字光标，点击胶囊空白处把光标放进输入框；禁用按钮（如未接通的 AI 加号、麦克风、发送）保持箭头。
- Mac 菜单栏提供「性能追踪」：开始、标记此刻、停止并导出。默认关闭，记录期间标题为「性能追踪 · 记录中」；不在卡片或阅读区新增悬浮入口。此入口是本机诊断工具，Web 不显示。

窄桌面仍在容纳两列最小宽度时保留两列；三列及以上才要求每列达到理想阅读宽度，避免小窗口退成过宽单列。

主页分栏滚动时保持可见。读完、完成提醒或勾选待办只更新状态，不改变当前信息流的成员、顺序、叠卡分组和卡片占位；任务预览保留当前行。切换分栏只应用筛选，保留卡片相对顺序。后台保存、内容更新、加载更多和返回主页不因完成状态重排；只有用户主动刷新或主动更换排序方式才重新排序。

## 移动浏览器基础行为

- 悬停反馈只在支持悬停且主指针精确时生效；按下与键盘焦点反馈独立保留。
- 应用与全屏阅读区域使用动态视口高度；Android 软键盘收起布局视口，iOS 继续使用现有 visualViewport 处理。
- 有触屏的设备上，输入字号至少 16px，避免聚焦时页面自动放大；保留用户缩放。16px 是浏览器输入保护阈值，不新增字号等级。
- 按钮禁止长按选中文字，正文和正文链接保留选择与系统菜单。轻点使用 manipulation，已有拖动区域保留自己的手势规则。
- 页面阻止浏览器纵向下拉刷新，内层滚动保留现有边界；横屏不自动放大文字。浏览器栏颜色跟随当前应用主题的 canvas。
- 这些是 Web 平台修复，不改变 macOS 的文案、状态或颜色角色；软键盘、安全区与主屏幕启动须在真机验收。
- PWA 触控与外壳：详情胶囊与底部导航的图标控件禁止文字选择和系统长按菜单。详情图标长按显示名称后，松手不执行动作；键盘聚焦时立即显示同一个名称提示。胶囊两端的名称提示向内侧展开，在 320px 宽度内完整可见。

独立工作台按系统深浅色选择状态栏底色：浅色 canvas 为 #f5f5f7，深色 canvas 为 #111113。登录页使用 card 底色，浅色 #ffffff、深色 #1c1c1f。manifest 保留现有 theme_color，不新增离线缓存。

主页隐藏浏览器根滚动条，不为右侧轨道预留空白；鼠标滚轮、触摸和键盘滚动保持可用。macOS 原生窗口不受此浏览器样式影响。
搜索结果、设置、AI 上下文、多选菜单和云端记一笔遵循同一隐藏轨道规则，仍可滚动到底；只隐藏滚动条，不使用 overflow: hidden 代替。

## 登录与授权

现行画板：[桌面登录](../boards/Login.dc.html)、[桌面授权](../boards/Authorization.dc.html)、[手机登录](../boards/LoginMobile.dc.html)、[手机授权](../boards/AuthorizationMobile.dc.html)。

- 登录内容宽度为 `auth-login-width` 352，授权为 `auth-consent-width` 400；窄屏按可用宽度收缩。两页采用白底、居中窄内容区与蓝色主按钮，不加外层厚卡片。品牌图标、连接图标、标题和状态说明居中；输入标签、账号信息和权限条目左对齐。
- 登录页使用 40 × 40 的应用图标和 `auth-title` 30/1.3 标题。输入框与主按钮高 44，表单标签与输入框间距 8。当前 Web 与 Mac 只提供邮箱、密码、显示密码和「登录并继续」，不显示邮件登录或邮件重设密码入口。标题下不加介绍句，页脚不加标语；从插件进入时说明登录后继续本次授权。
- 当前未启用生产邮件登录，服务端默认拒绝发信请求。既有邮件回跳保留兼容，不作为现行登录入口；不能用演示反馈表示真实登录完成。
- 授权页显示申请应用、当前账号、逐项权限和内容范围；删除权限单独列出。应用名称、账号和权限按实际请求显示，不能固定使用画板中的示例值。
- 授权按钮为“取消”和“允许访问”；保留“可在「已授权客户端」中撤销”。取消不得授予权限；允许后的状态须以真实回执为准。
- 手机画板按 390 × 844 展示，与桌面共用页面和交互。手机缩小两侧留白，图标和标题保持居中；输入字号至少 16px，按钮高度至少 44px，内容超出屏幕时可纵向滚动。保持相同的顺序、文案和状态。macOS 对应登录与授权界面沿用同样的居中原则和权限表达。
- 独立 Web 和手机 Web 未登录时进入 `/auth/login`，不在工作台另放一套邮件登录表单；已有未保存草稿时保留恢复入口。登录与授权画板从产品 HTML 和样式生成，仅替换演示回执，不提交真实请求。
- 原型页面只展示产品界面，不加顶部品牌栏、“设计预览”标识、页脚页面跳转或状态切换工具。画板之间从设计目录进入，状态通过页面原有操作触发。示例账号和必要的演示结果提示不进入产品页面；画板不提交账号、不发送邮件、不更改权限。

### 卡片详情内的导航与媒体

- 正文链接指向 Sill 内已有卡片时，在当前窗口打开该卡片，关闭后返回上一张；外部网址保持在来源打开。
- 播客上滑后，完整播放器切换为吸顶小播放器；不显示「正在播放」标题。大小播放区的淡化进度跟随滚动，只有当前主要显示的一组控件接收操作。小播放器与页签占据固定位置，页签的间距不随收起状态变化，文字稿从下方开始；滑回顶部或点标题恢复完整播放区。
- 卡面“审阅”有真实 PR 链接时打开该 PR；缺少链接时打开 Sill 中的 PR 详情，不禁用本地查看入口，不提交外部审阅。
